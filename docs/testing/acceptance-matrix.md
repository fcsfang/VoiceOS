# VoiceOS v0.1 需求验收对照表

日期：2026-10-10。状态：测试设计草稿；全部软件案例未执行。

依据：[PRD v0.1](../product/prd.md)、[产品决策与待定事项](../product/decision-register.md)。本表用于审查需求是否可验收，不替代架构阶段的详细测试计划，也不表示功能已经实现。

## 1. 执行与证据约定

每次执行记录：案例编号、版本、运行环境、输入/预置历史、授权配置、操作步骤、实际结果、判定及证据定位。AI 场景还记录模型、提示和配置版本及人工判定依据；样本不使用未授权的个人资料。

优先使用合成音频、可控的历史记录和沙盒提醒事项清单。失败注入需覆盖保存前后、模型调用前后、外部写入前后、恢复和权限撤销。不得用“请求发送成功”代替外部状态证据，也不得用文档检查代替软件验收。

涉及 P 项的案例，在边界确认后选择相应配置；涉及 H 项的能力须先获得验证证据。当前均未执行，执行结果另存报告，不能直接把本表设计预期改成实际结果。

## 3. 质量指标的口径草案

- 录音可靠性：分别统计已接收、已确认保存、受损/丢失的来源。故障注入记录中断阶段；不能把尚未保存完的录音当作已承诺安全，也不能因此省略录制中恢复测试。
- 处理完成率：分母为事先定义的有效测试录音；分子为规定观察窗口内无需人工修复、直接或自动重试成功的条目。无效/不支持输入另报，不能在运行失败后随意排除样本。≥95% 是愿景拟定目标，样本与时限待 H10/P05。
- 任务质量：明确行动漏建率、模糊愿望误建率、错误时间/期限分别报告；同时记录是否产生真实外部写入。
- 忠实性：否定、条件、归属、引用、术语分项标注；严重错误与普通措辞差异分开，来源必须能追溯。
- 关联质量：相关和不相关样本分别统计，评价证据是否支持关系；冻结的错误内容出现在可信结果中单列为阻断失败。
- 成本和时延：分阶段记录，区分休眠、离线、等待权限、模型和外部同步；P05 已授权小规模方案先测；产品预算与目标待测后校准。

## 4. 后续测试计划

技术验证阶段先获得实际设备/API/模型证据；详细测试计划随后定义样本集、环境、自动与人工判定职责、故障注入方式、回归执行和报告格式。

四周真实使用是愿景提出的验证建议，须观察自然产生的跨时间闭环与负担感，不要求每日打卡。人工准备的验收链与真实使用链分别报告，不能混成同一成功指标。
