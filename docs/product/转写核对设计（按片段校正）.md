# 转写核对设计（按片段校正）

状态：v4 · 2026-11-24

## 这份流程在做什么

语音识别给出初稿。核对把初稿变成此后所有理解、笔记与引用的唯一原文。它不是给用户看的审稿清单，而是产品的原材料生产线：校对到哪里，下游就能读到哪里。

此前的 v3 让模型返回「最小替换」：`before` 必须在某个片段内逐字出现、且只出现一次。这份协议把转写质量问题变成了字符串定位问题——同名短语、重复口头语、跨段断句都会让整份核对失败，再花两轮让模型重新定位。失败与转写质量无关。

v4 改成按片段校正：模型对需要改动的片段给出校正后的完整文字，片段身份与时间范围保持原位。本地按片段拼接、重算偏移。定位、重叠、重复出现这一整类失败消失。

## 数据形状

输入 `Qwen完整逐字稿.json`：

```
{ "text": "全文", "spans": [{"id": uuid, "textStart": n, "textEnd": n, "startMS": n, "endMS": n}] }
```

spans 首尾相接、完整覆盖 text，偏移按 Unicode 标量计数。

模型返回：

```
{
  "corrections": [{"span_id": uuid, "text": "该片段校正后的完整文字", "note": "改了什么、依据"}],
  "remaining_issues": [{"span_id": uuid, "reason": "仍不确定且影响意思的地方"}]
}
```

- 未列出的片段保持原样；不允许新增、拆分、合并片段。
- 本地应用后重算每个 span 的 textStart/textEnd，拼接成新全文。
- `user_corrected` 稿：校正文字必须与原片段逐字相同，模型的不同写法只作为疑点保留，不改原文。

## 提示词的分工

- 说明这份文字将成为下游唯一原文。
- 要求逐段读完全文，用词汇、领域知识与整段上下文判断实际说了什么。
- 列出识别最容易出错的位置：同音词、专名、术语与缩写、数字与量词、断句与标点、被切碎的口头表达；同一名称在全文统一。
- 给出成品的质量标准：读起来像这个人在完整、准确地说话；保留用词、语气、条件、保留意见与口头风格；判断与立场原样呈现。
- 疑点只记录确实不能确定、且影响意思的地方。
- 事实诚实：只读到了文字，没有听过音频。

不设角色、条数、字数、体裁与「不许」清单。

## 模型与强度

核对与整理脚本通过进程环境接收设置页的配置：

- `VOICEOS_TEXT_BASE_URL`
- `VOICEOS_TEXT_API_KEY`（只在内存与子进程环境，不写盘、不打印）
- `VOICEOS_TEXT_MODEL`
- `VOICEOS_TEXT_EFFORT`（设置页「核对与整理思考强度」）

应用内配置优先；导入的配置文件会转成同一组环境变量。Python 侧也保留读配置文件的退路，供命令行开发使用。

## 批量

笔记首页「待处理」多选后点「整理成笔记」：逐份核对（如需要）→ 生成笔记。单份失败不阻断其余，结尾汇总成功、被门控挡住与未完成的数量。

## 回执

`transcription_review` 记录 `context_review_version: 4`、`review_method: "direct_ai"`、`response_id(s)`、`correction_count`、`corrections`（展示用，单条截断）、`unresolved_issues` 与 `unresolved_span_ids`。Swift 端 v3 与 v4 都视为完整核对，历史材料不需要重跑。

## 已知边界

- 核对以单份录音为单位；连续表达的分段各自核对，跨段理解留给后续整理与笔记。
- 疑点只在材料页展示与回听，不阻塞笔记生成（门控只要求核对完成）。
