## 1. 文档约定与目标

需求以 `PRD-模块-编号` 标识；愿景出处使用原文节号和 D01–D10。下表中的“基线细化”将已有方向展开为行为与验收，仍需检查细化是否准确；“提案”是新增首版机制或边界，需审查后才能成为实施基线。P01–P06 是产品审查事项，状态以决策登记表为准，H01–H10 是技术验证事项。

首版目标：用户能低负担地表达，系统忠实保存知识和行动，并让下一次结果或表达回到源头，形成完整闭环。真实使用中，应减少找回旧思考和关联任务结果的手工整理。

首版不以笔记数、任务数、通知数、打卡天数或互动时长作为成功指标。一个未回应的非紧急反馈不代表用户失败。

## 2. 用户、场景与产品形态

首要用户是经常口头思考、阅读学习、研究和训练表达的个人；系统也要支持日常灵感与生活计划。首版以单个个人用户为工作范围；团队权限和协同编辑是范围提案中的延期项，不改变长期个人系统定位。

| 场景 | 触发 | 必须形成的价值 | 禁止的误解 |
|---|---|---|---|
| A 技术访谈与研究 | 用户评论访谈，并明确提出阅读行动 | 区分嘉宾与用户观点，任务连接猜想，阅读后表达更新历史 | 把嘉宾主张写成用户立场；完成阅读即“验证成功” |
| B 灵感复用 | 用户记录未成熟想法，数天后再谈相近主题 | 保存暂定认知，给出有依据的历史关联，用户可主动讨论 | 每条灵感都建待办；AI 关联推测当成确定事实 |
| C 英语表达 | 用户用英语讲解技术主题，后续再次练习 | 保留原句、表达建议、旧反馈和新练习的联系 | 用逐字稿推断发音分数或流利度 |
| D 生活计划 | 用户表达弹性安排或一般事务 | 明确行动与愿望分开，普通事务完成即可 | 无依据建立硬期限；强制用户补充认知反馈 |

近期：后台 VoiceOS Core 处理理解、记忆、规划和反馈；轻量控制中心提供录制、状态、阅读回溯、任务、对话、纠错和权限入口。Apple 提醒事项是主要任务执行界面。P03 已确认思源为可选集成，不成为首版依赖。

长期：完整独立应用逐步承载主要体验，第三方工具成为可选集成；来源、实体身份、关系、版本和授权不因界面迁移而丢失（D07）。

## 4. 核心旅程与结果边界

### 4.1 默认记录旅程

开始录制 → 自由表达 → 结束并可靠保存 → 用户可离开 → 后台转写与理解 → 保存暂定观点、问题、行动候选或授权任务 → 静默呈现结果。

结束录制后，“原始数据已保存”的反馈必须独立于“理解完成”。保存失败时明确说明，不能提示已安全保存。AI 未完成不会阻止用户结束会话；休眠可暂停处理，唤醒后续作。

### 4.2 跨时间闭环

查阅记录或完成提醒事项 → 获得行动状态 → 用户可选择补充结果或再次口述 → 系统检索既有记录 → 建立有来源的支持、修正、延续或待核对关系 → 分别更新认知和行动历史。

只有勾选任务时，可完成行动状态回流；没有结果依据时，认知状态保持不变。验收案例 A 仍必须包含阅读后的新表达与认知更新，不能用勾选动作替代。

### 4.3 主动对话与纠错

用户从记录、问题或资料主动进入 B → AI 使用授权上下文讨论 → 新表达、AI 建议与行动候选保持归属 → 回到同一认知体系。

用户更正误解 → 定位相关表达 → 明确错误后阻断其可信使用 → 检查派生知识、任务与关联 → 修复可确定部分，重要外部变更等待确认 → 保留纠错原因与历史。

语义不足以定位时，在纠错入口请求最少澄清；不能在模式 A 录音期间擅自插入语音追问。

## 6. 概念数据与状态约束

本节是数据模型的产品约束和状态提案，不是数据库表定义。

| 概念 | 必须能表达的信息 | 必须保留的关系 |
|---|---|---|
| Thought Event | 稳定身份、时间、主题与参与内容 | 来源、观点、问题、任务、后续事件 |
| Source | 用户/第三方身份、原始资料定位、已知时间、访问与处理限制 | 文本片段及其时段、材料上下文 |
| Transcript/Extract | 忠实原文、整理文本、片段及修订 | 来源、转写/整理版本 |
| Claim/Question | 原文或整理表述、作者/认可、证据、不确定性 | 依据、历史版本、支持/限定/矛盾关系 |
| Goal/Project/Task/Opportunity | 目标、阶段组织、动作、未承诺候选、时间表达、授权 | 意图来源、执行映射、结果和计划修订 |
| Outcome/Reflection | 结果内容、反馈来源、时间 | 原任务、原观点、新表达 |
| Relation/Revision | 关系类型、有效性、原因、来源、修改者/处理者 | 参与对象、版本与派生依赖 |
| Processing/Operation/Grant | 处理状态、权限、操作结果、重试身份 | 对应资料、产物和外部写入 |

认知归属至少区分用户暂定、用户确认、外部主张、AI 候选、归属待核对；证据状态至少区分未知/未验证、支持、受挑战和限定性验证。具体枚举待模型文档，不把“用户确认”放进证据枚举。

行动候选只有明确承诺或授权激活后进入正式任务。任务完成、结果反馈、新认知形成分别记录；删除、取消、延期和完成不能混为一谈。

纠错影响状态与观点内容状态独立：被确认错误或受错误派生影响的内容，可保留历史显示，但不作为可信当前记忆。普通主题关联不自动等同派生依赖，冻结范围应依据影响链。

处理可处于排队、执行、等待条件、失败、结果未知、完成等类别；外部同步另有状态。架构阶段须解释中断恢复、并发重试、权限撤销和结果核对，不能只靠模型自由文本维护状态。

## 7. 交互规格的首版边界

模式 A 无语音打断；处理中用户不必留在界面或审稿。结果默认显示简洁的个人暂定认知、问题、行动及状态；AI 候选和出处可展开，不用一个总分替代归属与证据。

模式 B 由显式操作开启并可结束；新对话使用授权来源和历史。引用外部材料、引用用户旧观点和 AI 建议要能辨别。首版文字对话是提案，非实时语音不影响基础模式 B 能力；是否增加按回合语音待 H03。

关联反馈显示“为什么现在相关”及依据；非紧急认知反馈默认静默，只有用户主动开启才发系统通知。用户可查看、讨论、稍后、减少类似提示或暂停，不制造未回应红点债务。任务的明确时效提醒按任务授权独立控制。界面细节在交互规格阶段完善，不提前规定菜单栏/网页/原生方案。

## 8. 授权、外部同步与纠错行为

### 8.1 动作权限矩阵

| 动作 | 愿景方向 | v0.1 的处理 |
|---|---|---|
| 录音、导入、转写、来源索引 | 用户动作和内容处理权限范围内 | P02 已允许文本与相关授权历史云端处理；麦克风权限不等同音频云端转写许可 |
| 用户明确观点暂存、AI 候选分析 | 已授权内容处理中可自动进行 | 不强制逐条确认用户原话；AI 新推论不冒充用户立场 |
| 普通明确任务创建 | 可在已授权任务范围自动执行 | P01 已确认高度自主；首次设置操作范围后不逐条审批 |
| 目标拆解、候选顺序 | 自动规划 | 可自主有限激活下一步；候选不全部变为一批提醒，无承诺愿望保留机会池 |
| 弹性任务自动排期/重排 | 在允许范围内 | P01 已允许高度自主；区分 AI 弹性安排与用户明确承诺，保留变更依据 |
| 修改明确期限、批删、重要目标取消 | 请求确认 | 展示影响和拟执行内容，确认前不写入 |
| 对外消息、付费、公开、不可逆承诺 | 单独授权 | 不作为首版跨应用执行能力；未来仍保留此边界 |
| 私密来源及其衍生历史检索 | 服从实际权限 | 无权上传时也不能通过历史摘要绕过限制 |

建议：授权撤销后阻止新的相关外部操作；待执行操作重新检查权限。已发出的不可撤回请求如实说明，不承诺撤销授权能撤回外部服务既有数据。此具体恢复机制需在 H04/H09 和架构中验证。

### 8.2 提醒事项同步的最低可观测行为

1. 每次 VoiceOS 创建都有来源和操作身份；创建后核对外部 ID 与字段。
2. 超时或进程中断时，状态是“结果待核对”，不是“未创建”；查明后才重试写入。
3. 完成状态回流保存观测时间；离线或权限失效时显示最后已知状态。
4. 外部编辑、改期、删除不能被重试静默覆盖或重建；在已授权范围可自主调和普通可逆变更，重要承诺或结果不明的情况保留待核对状态。
5. 仅同步授权范围和关联任务；是否读取其他清单用于规划待 P01/P02。

同步频率、接口方式、字段权威、同名去重和并发解决方案尚未确定。P01 的自主原则已确认，H05/H09 需验证执行和风险判断的实际能力；无法回读完成状态时报告需求冲突，不能宣布闭环已实现。

### 8.3 纠错与删除

纠错保留历史，以免错误被解释为用户观点改变；删除则按用户明确范围移除内容，并处理检索、缓存、衍生对象和外部副本。纠错历史不能成为拒绝删除的理由。

纠错影响有清楚依据时自动修复可确定内部部分；外部任务取消、重要计划变更等仍受执行授权约束。等待授权期间先阻止错误继续传播，不能等用户批准所有补偿才冻结记忆。

## 9. 可靠性、质量与可维护性

| 维度 | 首版要求或拟定指标 | 验证与限制 |
|---|---|---|
| 原始保存 | 测试期间零已确认原始录音丢失（愿景拟定目标） | 录制中/结束落盘/处理中分别注入中断；统计已接收和已确认保存范围，不能承诺任意硬件损坏零损失 |
| 处理可靠性 | ≥95% 有效录音自动处理完成（愿景拟定目标） | H10 定义有效样本、分母、观察时限、重试窗口和需人工修复情形；现在无实测成绩 |
| 忠实性 | 否定、条件、转述、引用和不成熟猜想专门回归 | 人工逐条判断严重归属/承诺错误；分别记录转写与理解错误 |
| 任务质量 | 分开评估明确行动漏建、愿望误建、错误期限 | 用标注样本计算各类错误，不用任务数量证明有效 |
| 检索与关联 | 找回相关历史，能够解释关联证据 | 区分漏检、误关联、无证据关系及错误记忆泄漏；阈值待 H07 |
| 成本与延迟 | 分阶段记录转写、理解、检索及同步开销 | P05 已授权先由工程选择小规模试验；月预算、典型录音长度和可接受耗时待测后校准；不能用固定“几秒完成”承诺掩盖休眠暂停 |
| 注意力 | 非紧急反馈默认静默、零强制回复；忽略不触发惩罚性催促 | 默认方式已获 P04 确认；开启后的预算/窗口待设计验证，观察负担感与自然使用 |
| 可维护与迁移 | 核心 ID、关系、版本和权限不依赖外部 UI | P06 默认范围已确认，正式数据导出恢复验证待 H08；模块通过契约复用，具体实现待架构 |

运行日志、调用元数据和用户可理解状态分层。AI 回归记录模型/提示/配置版本及必要依据，样本与日志权限受控制；不把完整个人历史复制进普通调试日志。

## 10. 三个端到端发布验收案例

以下步骤和结果必须真实可观察。测试可控制时间与准备历史样本，但真实使用验证还需观察跨时间复用；没有实现时均为“未执行”。

### A. 技术访谈与研究行动（AC-10）

- 输入：带节目来源的用户口播：“我怀疑检索质量比记忆容量更重要；我要查一篇论文验证。”
- 系统：保存原始来源和用户暂定猜想；外部说法与 AI 建议分开；在明确授权范围创建阅读任务并回读。
- 行动：用户在提醒事项中完成任务，VoiceOS 更新行动状态，猜想证据状态不自动改变。
- 新表达：“读完之后，我认为只在这个实验条件下成立，不能概括所有场景。”
- 验收：系统找到源头，连接新旧观点、任务和结果，保留最初猜想及限定依据；用户可从任务到观点、从新观点到原始片段双向回溯。
- 失败：只有孤立新笔记、仅勾选即认知验证、重复提醒事项、丢失出处或覆盖旧猜想，均不能通过。

### B. 灵感的跨时间复用（AC-12）

- 输入：第一次表达学习灵感，没有承诺行动；之后输入有共同主题但措辞不同的新想法。
- 验收：最初想法自动暂存，无无依据待办；新结果静默展示有证据的历史联系，标识 AI 的关系建议；可回听并主动进入 B，讨论成果回到历史。
- 负例：同样包含“学习”但主题无关的记录不得强行关联；忽略反馈不触发重复催促。

### C. 英语表达反馈循环（AC-19）

- 输入：英文技术讲解，以及包含相似语法/组织问题的后续练习。
- 验收：保留两次原句与来源；表达建议单独呈现；后续练习引用旧反馈并给出可复查的错误比较；转写误识别可修正。
- 限制：没有经过验证的音频专门评估能力，不显示发音、重音和节奏评分，也不将少量样本描述为全面掌握。

三个案例全部是愿景指定验收，不能只实现 A 后把 B/C 宣布为可选。详细故障、权限、纠错和迁移验收见配套对照表。

## 11. 验证与发布审查

文档审查：检查八类 MVP 能力、31 条需求及三个案例的覆盖；复核提案和已确认方向的区分；解决将影响实施的 P 项。

技术审查：执行 H 项，形成支持边界与备选方案；在架构、数据模型、ADR、实施与测试计划完成后才转入业务实现。

软件验收：执行对照表中的案例，保存证据；确认故障恢复、外部回读、授权、纠错阻断和可迁移路径，没有证据不能声称完成。

真实使用：建议四周自然使用，观察至少三条有意义闭环、旧观点复用、忠实度、通知负担、成本与纠错耗时。试用不要求每天打卡；样本和数值目标仍待 P05/H10 校准。

## 12. 未决问题与依赖

P01 高度自主行动、P02 文本/相关历史云端范围、P03 思源可选、P04 非紧急认知反馈默认静默均于 2026-10-10 获用户确认，详见[产品审查问题](review-questions.md)。实际清单和服务凭据仍需配置；原始音频未获默认上传授权。P05 已授权先选方案测试，预算指标待实测后确定；P06 默认导出、可选媒体打包、恢复前校验和不自动删除外部副本已确认；通知开启后的预算与窗口在后续设计验证。
