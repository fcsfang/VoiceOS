# 产品参照：三段结构与可借的成熟做法

用途：不是记录做过的修改。它回答一个反复出现的问题，下一个界面、下一个交互，先参考谁。

用法：动手前先写下这个界面属于哪一段、听谁的。写不出来，才是需要原创设计的地方。

## 1. 产品是三段

抓取、归纳、承诺，再回到阅读面。愿景 D10 要求承诺和结果能回到源头，这是三段的接缝，不是第四段。

每段都有成熟参照。没有哪个产品三段都做得好，所以拼装是对的。拼装的前提是每一段只跟随一个参照，而不是三条都从零想。

## 2. 抓取

原则：抓取时不决策。分类、命名、主题都推迟到归纳。GTD 把收集和澄清分成两步，所有好用的收集工具都遵守这条。

| 参照 | 成熟做法 | 对 VoiceOS 的用法 |
|---|---|---|
| 语音备忘录 | 一次点击开始，自动命名，不要求元数据 | 已做到。抓取页只有一个动作，保持 |
| Drafts | 所有输入先落一个收件箱，之后再决定去向 | 录音、外部资料、AI 资料进同一入口。已有 |
| Granola | 用户随手写下的几行字是意图层，转写是事实层，AI 填中间 | 录的时候允许随手打字，归纳时优先采用手写内容。可做，未做 |
| Readwise 导入 | 多来源统一成一种材料形状 | 已经是这个形状 |

不借：会议纪要的仪式（参会人、模板、行动项表格），那是企业形状。抓取时要求打标签，那是把决策提前。

## 3. 归纳与阅读

原则：阅读面的第一美德是安静。排版服务于读，界面元素让位。

| 参照 | 成熟做法 | 对 VoiceOS 的用法 |
|---|---|---|
| Readwise Reader、Kindle | 正文宽度、行距、字号阶梯有纪律；记住阅读位置；划重点 | 字号与宽度已落地，位置记忆已有。让用户自己标记「对我重要」作为回看单位，可做，未做 |
| Readwise 每日回顾 | 旧摘录按固定节奏重新送到眼前 | 回看优先于堆积。知识核查接近这个，但由任务触发，不由节奏触发 |
| Day One、日记类 | 时间轴是主轴，主题是副轴 | 首页左侧日期、右侧主题，已经是这个结构 |
| Obsidian 双链 | 关联出现在文内，而不是一张独立的全景图 | 关联要落在就近引用。警惕图谱好看不好用 |
| 引用式综合（Perplexity 一类） | 每句结论能落到来源 | 引文与证据引用已有，保持 |

不借：把图谱当作导航首页。AI 自动整理到用户无法预测东西为什么在这里。

## 4. 承诺与行动

原则：承诺只有落到某一天才真实。GTD 的澄清决定什么算承诺，Things 的今天决定今天做什么。

| 参照 | 成熟做法 | 对 VoiceOS 的用法 |
|---|---|---|
| Things | 今天、即将、随时三个时间面；截止日与「何时做」分开 | 行动页现在是分类清单加逐行到期信息，没有「今天」这个面。这是三段拼接里最明显的缺口 |
| GTD | 收集、澄清、组织、回顾、执行；下一步行动与将来也许分开；每周回顾 | 待办与问题与目标已经是下一步行动与将来也许的形状。缺澄清这一步，也缺每周回顾 |
| Todoist | 一句话快速添加 | 语音加 AI 抽取本身就是这个能力。保持随手可加 |
| OmniFocus | 按情境和视角切片 | 不借。单用户日常用不到，负担大于收益 |

不借：看板、优先级矩阵、多人指派。个人承诺不需要项目管理的形状。

## 5. 拼接

1. 一个表面只认一个参照。阅读面听 Reader，行动面听 Things，抓取面听语音备忘录。不要把清单放进阅读页，也不要把长文放进行动页。两种交互模型同屏，就是界面变脏的来源。
2. 共享层只有一套。字号阶梯、颜色角色、圆角、间距是拼接的胶水。这轮的全局字号与 `WorkspaceMetrics` 就是这一层。
3. 接缝是原创所在。想法变成承诺、承诺显示原话出处、完成回流到阅读面，没有哪家参照产品做得好。这三处不要抄，要自己设计。

## 6. 遇到新问题先查的名字

| 问题 | 查这个名字 |
|---|---|
| 该不该折叠 | 渐进披露。只折叠次要信息 |
| 两个地方显示不一致 | 单一事实来源。一个概念一个查询 |
| 外部写入可能重复 | 恰好一次副作用。预留态、操作日志、对账 |
| 页面没有数据 | 三态设计。空态、加载态、错误态 |
| 界面读起来吵 | 排版层级。角色化字号，写成 token |
| 要不要做更多回顾功能 | 回看优先于堆积。知识库的价值在重访 |
| 能不能把两个功能放一页 | 一个表面一个参照。不混交互模型 |
| 抓取时要不要让用户分类 | 抓取与澄清分离。抓的时候只抓 |

## 7. 参照的边界

- AI 生成个人知识摘要怎么呈现，还没有定型答案。这部分自己探路是对的。
- 单用户、本地、私密。多用户、权限、同步的成熟方案不适用。
- 不整套照搬。Material 或完整 GTD 都会压掉产品自己的声音。取原则，不取成品。

## 8. 候选参照（尚未采用）

这一节是扩展菜单，不构成承诺。判断标准只有一条，它是否强化抓取、归纳、承诺、回流的闭环。

### 抓取

| 参照 | 可借的机制 | 对 VoiceOS 的用法 |
|---|---|---|
| Drafts、Raycast | 系统级快速捕获 | 不打开主窗口就能录一段或写一句 |
| Readwise Reader、Notion Web Clipper | 网页与 PDF 正文提取 | 现在只收 txt、md 与音视频，读的东西进不来 |
| Todoist | 一句话带动作和时间 | AI 已在抽取，缺更快的入口 |
| Apple Journal、Day One | 提示式捕获 | 空白页难以下笔，给一个温和的问题，不做打卡 |

### 归纳与阅读

| 参照 | 可借的机制 | 对 VoiceOS 的用法 |
|---|---|---|
| Kindle、Readwise | 用户划重点 | 现在单位全是 AI 抽取，缺「这句对我重要」 |
| Audm、播客类 | 听回整理 | 语音优先的产品，阅读面却只能看 |
| Anki、Readwise 每日回顾 | 间隔重复 | 知识核查由任务触发，不由记忆节奏触发 |
| Obsidian 双链 | 文内关联 | 关联出现在判断旁边，不做独立图谱首页 |
| Kindle Word Wise | 就地查词与朗读 | 用在英语练习，范围小但贴合 |

### 承诺与行动

| 参照 | 可借的机制 | 对 VoiceOS 的用法 |
|---|---|---|
| GTD 的 Waiting For | 等待外部 | AI 代办和依赖他人的事需要独立状态 |
| Things、Reclaim | 日历时间块 | 承诺落到某一天之后，下一步是落到某个时段 |
| OmniFocus 的 review interval | 每个主题的回顾间隔 | 主题和问题可以有自己的回顾节奏 |
| Linear 的 ⌘K、Raycast | 命令面板 | 跳转到任何材料、任务、主题并执行动作 |
| Obsidian、Notion | 搜索语法 | `type:task`、`before:2026-10`、`topic:...` |

### 不借

- 看板、优先级矩阵、多人指派、打卡连击。项目管理或增长形状，会把个人承诺压成工作流。
- 会议纪要模板。企业形状。
- 图谱当导航首页。保留全景，但不扩张成默认入口。

### 如果只做三件

1. 用户划重点。补阅读面最大的代理权缺口，成本小。
2. 全局快速捕获。补抓取入口，成本中等，直接提高使用频率。
3. 听回整理。把语音优先延伸到阅读面，差异化最强。

## 9. 扩展候选库

这一节是完整研究版，第 8 节是短名单。机制描述来自产品观察，未逐个复核，落地前先验证。成本 S 指一两天内能验证，M 指数天到一周，L 指需要新子系统或格式变更。影响是用户能感觉到的收益。这里没有优先级承诺，取舍时看当前闭环的瓶颈。

|---|---|---|

| 稍后预设 | 改天先给今晚、明天、下周、自定义四个预设，底层写现有提醒日期 | 中 |

| 隐私清单 | 用 `PrivacyInfo.xcprivacy` 声明 required-reason API 与数据类别 | 中 |

### 9.6 明确不借

- 项目管理形状。Areas、Projects、sequential/parallel、依赖、阻塞、周期、看板、优先级矩阵。
- 团队协作形状。共享清单、指派、评论、团队排期、会议协调。
- 增长形状。连击、Karma、队伍、习惯打卡。
- 插件体系。安全、兼容和维护负担，单用户产品不划算。
- CRDT 与 iCloud 同步。与单用户、本地优先定位冲突；若做只能作为可选、端到端加密的附加层。
