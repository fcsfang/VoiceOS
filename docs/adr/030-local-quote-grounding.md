# ADR-030 分段引用由本机精确定位

日期：2026-10-12。状态：开发采用，真实新批次待验收。

真实长文字调用返回的 21 项提案均有唯一原话匹配，但多数数字位置错误，因此整段被严格校验拒绝。该批次保持 rejected，不修改历史响应、不重发。转写质量和引用位置计算是两个独立问题。

选择：新的 `segment-extraction-v2` 只请求 kind、statement、quote；本机通过 Unicode scalar 逐字匹配生成位置与相交来源身份。不存在、重复或拆开完整字符的引用均拒绝，不做模糊纠错。旧 v1 数字协议仍可显式选用。保留严格最终校验，原话更正继续使旧范围失效。

备选：继续要求模型算数字会重复此次可靠性问题；模糊匹配会改变证据；自动接纳旧拒绝响应会改写历史，均不采用。本机定位能保证出处，不能保证模型语义或证据覆盖正确。

完整账本含身份、引用和处置元数据，真实首段重建约 24567 scalars，原 4000 预算不足。仅当提取与聚合都为 v2 时，默认/上限扩为 32000；混合或旧端口维持 4000，显式旧预算不变。聚合协议为 `segment-aggregation-v2`。仍保留 160000 字节请求上限，不裁剪账本；超限明确停止。代价是潜在文本费用与延迟增加；此处是上限，不保证代理接受或完整长稿适用。

跨段未完句继续阻塞聚合，不能为验收删除边界证据。未改变 schema31 或历史范围摘要格式。相关 21 项测试通过，涵盖唯一精确定位、字符边界、v1、v2 HTTP 夹具/持久复用和混合端口预算；未重跑全套回归、未调用新真实云端请求。
