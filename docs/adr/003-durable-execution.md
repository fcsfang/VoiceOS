# ADR-003 持久处理与外部操作恢复

日期：2026-10-10。状态：partially_adopted（开发切片）；其余仍 proposed。关联：D05/D08/D09、H05/H08/H09。

**问题与约束。** 用户离开、断网和睡眠后必须续作；AI 具有普通行动自主权；未知外部结果不能重复执行，旧回调不能复活已纠错/删除内容。

| 备选 | 收益 | 代价 |
|---|---|---|
| 本地持久 jobs + outbox + 租约/版本 + 外部核对 | 同库原子安排工作，少部署，故障可解释 | 必须实现恢复状态机与窗口测试 |
| UI 内存异步任务 | 原型简单 | 退出丢工作，缺身份和未知结果核对 |
| 外部队列/工作流服务 | 长流程工具与监控丰富 | 运维/联网依赖多；仍不自动解决 EventKit 外部去重 |

**推荐。** 第一项。内部采用单 writer、CAS、稳定逻辑 job/operation 身份和递增租约 epoch；调用前记录 sending，成功回读再确认。重试是 attempt，不是新任务。AI 提案与确定性执行分层，普通操作按持续授权自动执行。

**代价与边界。** 文件、DB、模型请求、EventKit 无统一事务。内部租约不能 fence 外部调用；未知操作只核对，缺可靠否定证据时停留 unknown，而不是承诺外部 exactly-once。模型超时可能计费，重试预算不可无上限。

**证据/采用条件。** 合成模型检查过丢回执、延迟、多匹配、编辑和撤销；实际 EventKit 故障与并发未测。按[状态机](../architecture/state-machines.md)和 AC-13/14/15/17/18 注入真实窗口，另核对晚到回调/纠错/删除；通过后采用。若本地流程规模超出维护能力再引入工作流服务，保留身份与外部核对协议。

**M1 采用范围。** 导入原子登记与本地转写持久 job/attempt/token 已采用并做真实进程退出恢复。外部 outbox、跨进程租约/epoch 和纠错删除屏障未实现。 证据与局限见[M1 实施记录](../engineering/m1-file-input.md)。
