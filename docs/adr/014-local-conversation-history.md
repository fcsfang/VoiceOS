# ADR-014：模式 B 的本地会话历史

日期：2026-10-11。状态：partially_adopted，仅会话/用户回合基础；AI 回复与界面未接入。产品依据：D01/D02/D04/D09、P07、PRD-DIA-01/02。

## 决策

会话作为 VoiceOS 核心对象，选定历史引用持久 LocalTranscriptContext；用户回合关联已保存的个人来源，独立保存当时上下文/文本版本。文字与个人音频使用同一关联接口，外部/未知说话者资料可以作为历史，但不能成为用户回合。

进入、追加、结束使用不同命令身份和会话版本；重复命令只返回旧回执。事务保存回合与版本一起提交。正常来源更正/权限变化在原事务里冻结依赖会话；读取重验，冻结保留旧原文供回溯。结束只结束讨论，不认可观点或制造任务。

迁移包 v14/schema15 新增 conversations、conversation_user_turns。恢复保留身份、历史和结束状态，并冻结会话，需用户显式从当前来源进入新会话才能继续；不假造用户退出，也不恢复执行授权。

## 备选与取舍

| 方案 | 优点 | 未采用原因/成本 |
|---|---|---|
| 仅保存聊天界面状态 | 实现快 | 重启/迁移丢身份，语音与文字难复用，归属和纠错依赖不可靠 |
| 每轮复制原文为独立聊天文件 | 易查看 | 重复原件、版本/隐私漂移，需要维护第二套历史 |
| 共用受管来源＋上下文＋会话关联，采用 | 来源/权限/更正与导出契约复用 | 每次关联需要重验；可能留下未被引用但无执行效力的准备上下文，不能将它当已发生回合 |

资料保存和关联是两个明确结果：原件可保存成功而会话关联失败；返回关联成功前必须完成回合事务。真实捕获/转写与关联的自动恢复配方在后续界面切片补齐，不能当前承诺录音完成即已加入讨论。

开发限制：入口历史4,000 Unicode标量，当前每个个人来源同样4,000；本地会话最多40个用户回合，超限拒绝，历史不截断。不是完整多轮模型的上下文窗口；后续实际发送范围与预算另存并实测。

采用证据见[实施记录](../engineering/m4-conversation-foundation.md)。GPT-Live 和订阅接入独立于本地数据身份，不能将缺少语音接口变成删除原件或迁移能力的理由。
