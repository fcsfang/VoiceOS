# ADR024：转写前的显式录音处理请求

状态：已实现。日期：2026-10-12。

问题：用户选择录制后处理，但逐字稿尚不存在；内存中的待处理标记在退出后丢失，直接构建模型队列则无法固定原话/片段版本。

备选方案：

1. 内存标记：简单，但无法恢复、迁移或审计，拒绝。
2. processing_intents 增加空逐字稿阶段：少一张表，但削弱快照不可变性和已有历史验证契约，拒绝。
3. 独立 recording_processing_requests，转写后以稳定命令移交原队列：多一张表和一次交接，但能保留开始录制时的选择并复用全部模型执行边界，采用。

录音来源、单来源文本授权和请求在一个事务中提交，随后才开启设备。队列交接不嵌套现有队列事务；提交后使用稳定请求命令查询回执，核对来源/授权/模型身份并补登记。取消处理覆盖这个交接窗口。未封存、转写失败、权限变化或配置变化不能触发新的模型调用。

请求表推动 schema26；包含它的迁移包使用v26，并在恢复后冻结。没有请求的资料库保持旧包输出范围，旧客户端明确拒绝不能解释的新格式。没有增加后台自动授权、模型重试或音频云端能力。

工程契约和验证：[录制处理请求](../engineering/m4-recording-processing-request.md)。
