# ADR-002 存储与检索

日期：2026-10-10。状态：proposed。关联：D07/D09/D10、H07/H08。

**问题与约束。** 需要原始资料、版本和关系的稳定身份，内部原子提交，跨时间检索和纠错后即时阻断；迁移不能只靠外部笔记。

| 备选 | 收益 | 代价 |
|---|---|---|
| SQLite + 独立媒体 + 可重建检索投影 | 单机事务与约束集中，部署轻，逻辑导出可读 | 文件/DB 跨资源窗口要恢复；中文/语义召回另验证 |
| Markdown/JSON 文件直接作全部主存储 | 用户易读，工具通用 | 多对象原子更新、版本引用、并发删除和 outbox 需另造机制 |
| 图数据库/云数据库作主存储 | 图遍历或多设备服务能力较强 | 安装/服务与迁移成本高；概念关系不证明首版需图数据库 |

**推荐。** 第一项，类型表 + 对象版本/依赖/权限记录；媒体原件独立封存。结构/时间/关键词检索与可替换语义索引组合，索引可删除重建，不成为唯一历史。若无需独立向量服务即达到 H07，优先较少依赖的实现。

**证据和不足。** SQLite 合成中断/唯一性和逻辑包恢复已测，见[可靠性报告](../research/reliability-validation-2026-10-10.md)。未证明真实音频跨资源持久化、中文召回、语义负例过滤或最终 schema 升级。

**采用条件与退出。** 真实中断和媒体闭包快照、版本/删除恢复、H07 正负例通过后冻结；不能以关键词碰巧匹配替代跨时间关联。未来改存储依靠版本化逻辑导出/迁移工具；不用共享数据库文件充当设备同步。
