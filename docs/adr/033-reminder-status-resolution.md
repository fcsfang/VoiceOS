# ADR033：提醒事项状态冲突的本地恢复

日期：2026-10-13。状态：本轮采用；路线 W14，PRD-ACT-04、PRD-REL-02/03、PRD-CTRL-02。产品方向与授权不变。

## 问题与选择

外部重开与本地完成，或本地暂不跟进与外部完成，会保留为 conflict。当前只有通用本地状态按钮，缺少绑定具体外部观测的恢复途径；通用重开也不能更新同步基线，之后再次外部完成会一直冲突。

新增显式“采用提醒事项状态”，只把用户看到且重新核对未变化的外部完成/未完成状态用于修订本地 Task。它不是普通任务的逐项审批，也不是认知结果确认。唯一标记、授权清单、外部身份、观测身份、本地行动版本必须匹配；缺项、多项、标记损坏、迟到、冻结或撤权时不接纳。运行前后重验，未知结果不重建。

备选方案：①沿用通用状态按钮，没有观测依据或可恢复的同步基线；②直接改写现有 link.action_version，破坏历史完成观察的版本校验；③增加不可变状态恢复记录，保留创建基线并从最新恢复修订派生后续同步基线。采用③，以一张追加表换取历史可追溯与后续自动完成回流。后台自动解决所有冲突尚未具备足够的字段权威与三方比较，暂不隐含实现。

## 持久与迁移

schema32 新增 reminder_status_resolutions，绑定 link、唯一观测、用户行动修订、恢复前同步基线与当时持续授权版本。创建 action_version 不变；最新恢复的行动版本用于后续完成回流。行动修订、恢复记录与 link 状态在同一事务提交，不跨 await 持有事务。

存在恢复记录时导出包 v32，包含此前全部表与恢复记录；旧包仍可恢复。导入验证绑定身份、动作/观测状态、版本顺序、修订与命令摘要，并检查外部反馈对应发生时的同步基线。恢复记录仅是历史，不携带提醒事项连接授权；空库恢复仍须重新连接。没有恢复记录的旧 schema31 升级只增加空表。

## 本轮边界

不创建、删除、改名、改期或勾选真实外部任务，不生成用户口吻 Outcome，不升级 Claim 的归属或证据。期限三方调和、外部补偿及自然案例 A 仍分别未验收。当前恢复入口由用户选择；之后普通外部完成继续按持续授权回流。
