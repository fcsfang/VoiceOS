# ADR027：片段尝试独立持久化，结果暂存至整篇聚合

日期：2026-10-12。状态：partially_adopted。通用提取端口及本地验证、持久尝试采用；真实云端驱动和聚合未采用。

问题：片段不是完整来源；原ModelPort/contexts/回执复用绑定完整逐字稿。将片段伪装成完整上下文会混淆回执，将各段直接提交claims会在后文取消前产生任务。

备选：放宽旧上下文校验（破坏历史契约，不采用）；为各段复制个人文字（丢失父引用并导致部分行动，不采用）；独立片段尝试加暂存域（采用）。代价为schema28/包v28、独立usage读入口与深层恢复校验；收益为完整父身份、未知不重发和取消后的迟到证据保留。

producer_sequence采用原model_attempts与新尝试表的共同最大值，唯一Store写入者在无await的预留事务分配；读取/恢复校验跨表无冲突。独立两个表自增会让相同序号含义不清，因此不采用。统一生产者注册表适合更多管道时再迁移；现阶段没有新增注册表及所有旧外键改造。

调用输入只带一个片段及原全局引用，政策/模型身份固定。完成响应只暂存证据与已知usage，认知/任务实体数量保持0。来源变化立即阻塞父批次并冻结子结果；迁移全部冻结，无自动模型派发。整篇消费必须从持久成功回执构建账本，不能使用任意本地提案作为执行资格。

验证及未实施范围见[实施记录](../engineering/m4-segment-extraction.md)。后续聚合需要独立attempt和原子认知提交，不能把片段完成数当作MVP验收。退出方案是暂停父批次、保留可迁移的回执/用量和原文，保持旧完整文字管道独立可用。
