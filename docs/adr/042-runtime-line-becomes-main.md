# ADR042：运行时线成为产品基线，main 反迁其独有工作

日期：2026-10-29。状态：采用。

## 问题与选择

两条线在 `2f6e533` 分叉。运行时线有 220 个提交、schema 49、统一工作区、主题与反思、AI 助理、知识核查，是用户实际在用的应用，实时资料库也在这一线。main 有 25 个提交，其中代码大部分是运行时线 `3742927` 的重放，而 `3742927` 是迁移快照 `6559b45` 的父提交。快照新增的 105 个文件、schema 40 到 47 从未进入 main。main 又把全景表编成自己的 schema 42 和 43，导致两条线的 schema 43 含义不同。main 打不开 schema 49 的资料库；运行时打开 main 的 43 库会先执行 43 到 45，再在 45 到 46 失败，留下半迁移状态。

备选：①继续把运行时线迁入 main，约 9,400 行源码、83 个文件、6 个迁移和 schema 桥接；②两条线长期并存；③以运行时线为产品基线，把 main 的独有工作反迁并合线。采用③。资料库在运行时线，反迁只需要约 150 到 200 行应用代码、测试拆分和流程文档，并且不产生第二套 schema。

## 已实现契约

main 的独有工作进入运行时线后，main 的历史通过合并提交保留，旧 main 的树保存为 `archive/main-migration-20261028` 标签。运行时线继续使用 schema 49 和 `PortablePackage` 1 到 47。英文练习、静默回顾、语义搜索、观点转行动、本地排期、分段预览和跟进摘要在运行时工作区恢复可达。工作流、验证技能、`work/` 记录和测试拆分进入新基线。两条线不再并行开发。

## 验证与边界

运行时基线在合线前 `swift test -j 4` 10 项通过，合线后重新运行并在真实资料库副本上验证。旧 main 的 schema 43 资料库不在本次迁移范围内。若要保留，只能经 `PortablePackage` 导出后恢复，不能直接用运行时构建打开。schema 43 的双重含义保留为历史事实，新基线不做兼容层。
