# ADR041：纠错影响追踪完整处理与成果复用输入

日期：2026-10-13。状态：采用，W16既有依赖覆盖增量；依据PRD-COR-01/02、PRD-CTRL-03，接续[ADR040](040-corrective-reminder-due-compensation.md)。

## 问题与选择

已有冻结屏障会使完整上下文、讨论AI派生和共享成果暂停，但行动影响只查看claim直接引文。未被引用的背景逐字稿更正，或复用成果上游输入更正，会冻结行动却没有可见错误根；context_anchor尤其不能代表完整AI输入。

备选：①只追踪引文，漏掉实际依赖；②把同主题来源/整段会话当前内容都视为依赖，误将未参与早期处理的后续发言归入错误根；③从不可变处理身份、完整context_inputs及成果snapshot.reusePlan逐级追踪。采用③，不新增通用图谱表或产品“认知路线”。

## 已实现契约

`correctionInputVersions`从claim原attempt开始，读取该处理的完整context_inputs；成果复用只沿保存的priorResults.attemptID→contextID边回溯，校验对应身份，按已访问producer去重。不会从同一context反查未来/其他处理，也不读取后来追加的会话发言或相似主题。

`correctionRoots`共用于当前影响投影与补偿历史验证：直接认知纠错仍绑定行动引用的review版本；逐字稿根须是实际输入版本之后的transcription_error。根说明明确“处理或复用输入”，不冒充用户承诺、逐字引文或已证明任务错误。隐私变化、迁移冻结和早于实际输入版本的旧更正不构成新错误根。

当前影响digest同时绑定整个可追溯输入集合的来源状态/权限/当前文字版本/hash。未被引用背景的授权变化也会停止既有补偿计划。历史补偿允许旧根子集但仍须全部确实存在于实际依赖；不放松原排期链/效果/一次尝试校验。原冻结策略保持，scope仅补齐影响追溯与许可失效，不重新理解或外写。
