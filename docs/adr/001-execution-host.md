# ADR-001 引擎与控制中心宿主

日期：2026-10-10。状态：proposed。关联：D02/D07/D08、H03/H09。

**问题与约束。** 近期后台核心和轻量控制中心要共享稳定历史，录制与提醒事项需要原生权限；睡眠允许暂停，恢复不能依赖窗口仍开着。

| 备选 | 收益 | 代价 |
|---|---|---|
| 单 Mac 应用，Swift Core + SwiftUI | 原生权限身份集中，模块少，窗口与处理可分开 | 首版复用偏 Apple 平台；最低系统/分发需验证 |
| Web 控制中心 + Python 引擎 + 原生桥 | 复用现有探针，网页跨平台 | 多进程生命周期、权限身份及安装/协议维护增加 |
| 独立守护进程或云端常驻引擎 | UI 退出仍可处理，未来多设备便利 | 首版不需要全天在线；权限、数据上传、部署和恢复更复杂 |

**推荐。** 首版采用第一项，Core 用可复用 Swift package，平台功能通过接口隔离。关闭窗口继续处理，真正退出/睡眠后持久任务恢复；不以临时探针应用为生产宿主。

**证据和不足。** 本机 Swift 与 EventKit 正常单项路径可用，见[实测](../research/api-reminders-validation-2026-10-10.md)。尚未验证录制中的睡眠/磁盘故障、稳定签名身份、正式安装升级和 B 交互。最低 macOS 不因本机版本就冻结。

**采用条件与退出。** 完成录制入口/权限、关窗与退出区分、重启恢复及连续身份实验后采用；如需更低系统或跨平台入口，比较桥接代价再修订。未来可拆宿主，保持 Core 命令、内部 ID 和导出契约；分进程必须新增权限/IPC 验证。
