# 044 全局综合的紧凑引用输出

- 状态：已采纳
- 日期：2026-11-01
- 相关：#55、PR #57、PR #58、`docs/adr/043-panorama-sliced-generation.md`

## 背景

分片生成落地后，真实资料库副本重跑首次达到 25/25 单元核验，partial 快照含 138 个问题，单元核对一次通过。流程第一次进入 `global.synthesize`，两次因网络错误失败后，第三次在 561 秒时以 `status=incomplete, reason=max_output_tokens` 结束：模型在 65,536 输出 token 上限内没有写完全局提案，即使提高上限，600 秒的服务端流窗口也会先到。

量化原因：25 个单元提案的 JSON 合计 210,464 字节，综合要求模型把它们合并后重新输出一份完整提案，光结构化输出就超过单次窗口可生成的范围，再叠加推理 token 更不可能。单请求整份输出的合成在结构上不可行。

## 决策

全局综合改为紧凑结构输出，证据不再由模型重抄，而是引用单元问题。

- 综合请求的输入不变：`PanoramaIndex` 与全部单元提案（含各自的证据与观点）。
- 综合响应改为紧凑 schema：区域、问题、联系仍由模型命名与组织；每个问题给出 `evidenceRefs`，即单元问题 ID 列表（形如 `unit[uid]/part[n]/q_...`）；每条联系的 `fromEvidenceRefs`/`toEvidenceRefs` 同样引用单元问题 ID，且必须是端点问题引用的子集。未表达清单由端口在展开后按完整 manifest 本地重算补集；模型给出的原因作为说明，缺失项用固定原因补齐。
- `ResponsesPanoramaPort` 在本地把引用展开为完整提案：按 ID 从单元提案复制证据（去重），联系的证据来自被引用单元问题。展开后的提案必须仍通过 `validatePanorama`，现有问题/联系/覆盖/一致性核对一步不改。
- 未知引用、空引用、联系引用超出端点范围都视为模型输出错误，新增可重试的引用失败类型，重试一次后按单元级安全失败处理。
- 综合修复（`repairSynthesis`）使用同一紧凑形状，引用目标改为当前提案自身的问题 ID，展开时从当前提案复制证据。修复请求的输入仍是完整提案与拒绝报告，输入大小不是瓶颈。
- 综合与综合修复步骤使用独立的身份后缀 `|compact-synthesis-v1`，不影响单元步骤的既有回执与复用。

## 备选

- 提高 `max_output_tokens`：561 秒已经逼近 600 秒窗口，提高上限只会把 token 上限失败换成流窗口失败；拒绝。
- 降低综合推理强度：输出结构本身已超过窗口可生成范围，降低推理无法把结构缩到可完成；且以质量为代价；拒绝。
- 按单元分组综合再机械合并：组间语义重复与跨组联系会丢失，最终合并仍要一次输出整份提案；拒绝。
- 让模型只输出问题骨架、证据由后续逐个问题补齐：问题数量不确定，请求数不可控，且证据归属仍需模型；拒绝。

## 后果

- 综合输出从数百 KB 降到数十 KB，单次请求可在窗口内完成；证据由本地按 ID 复制，逐字与偏移天然正确。
- 覆盖清单由本地重算，模型误报或漏报未表达项不会导致综合失败，也不会隐藏任何已提交材料；真实运行的第一次紧凑综合正因模型无法自行算出展开后的覆盖补集而失败，故改为本地记账。
- 综合只能引用单元问题已有的证据；单元问题未覆盖的原话不会出现在全局问题里，由覆盖核对与未表达清单兜底。
- 模型需要正确使用单元问题 ID；错误引用会重试一次，仍失败则该次综合失败、单元结果保留、可明确重试。
