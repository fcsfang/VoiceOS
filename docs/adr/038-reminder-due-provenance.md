# ADR038：期限字段归属与后续弹性重排

日期：2026-10-13。状态：采用。路线W14，接续[ADR037](037-effect-bound-schedule-confirmation.md)；产品边界仍为P01普通任务自主、重要效果具体确认。不是新的长期授权种类。

## 问题、备选与取舍

第一轮AI安排执行成功后，所有已有外部日期仍被视为人工字段，第二轮普通弹性重排就必须再次确认，阻碍已授权的自主跟进。反过来，仅凭目标日期一致就认定AI所有，会覆盖人工编辑或把丢回执的未知效果误当作自己的写入。

备选：①所有日期永久按人工处理，安全但缺乏连续自主能力；②匹配目标日期就认定AI所有，无法区分人工写入与未知请求；③保存可回溯字段依据，以保存应答＋唯一匹配观测＋连续未变的时间观测作为普通弹性基线。采用③；仍承认未被观测的人工编辑/iCloud竞态不能从EventKit证据中排除。

独立 `reminder_schedule_bases` 记录新意图的历史归属和可选先前operation，而不重算所有旧意图。它在意图之后、所有操作之后导入，避免意图和操作间的循环插入依赖，也保留旧schema34–36语义。观测之后才恢复的旧unknown不能追溯修改当时的保守归属。

## 归属规则

1. 前一排期为用户明确承诺，继续按承诺保护；AI不得改写或降级。用户主动选择变更仍需具体效果确认。
2. 同一link/行动版本的先前AI弹性操作须为confirmed且保存应答和结果观测齐全；结果序列不晚于新基线。只有observed、unknown、conflict或迁移冻结操作不能作为运行时自主依据。
3. 从结果到当前基线的每项时间观测都须保持同一external ID、有效标记、未完成和同一due。中间日期被人工改过再改回、未知时间或身份变化都会失去连续依据；另一字段改名可以保留期限归属，条件保存仍保护当前人工标题。
4. 不能有更晚已尝试操作遮蔽这一依据。后续执行继续核对持续授权、最新来源/认知/行动/排期，以及新鲜外部快照；归属证据不能越过这些屏障。
5. 初始所有已知观测都无期限且没有先前写入尝试时，可按空白字段安排。人工移除过日期或经过未知时间再回到无期限不能冒充初始空白，须具体确认。
6. 意图保存后，预览及执行屏障再次检验当前连续依据。观察到期限变化后，即使又改回原日期，也必须保留remote并形成新排期版本，不能消费旧弹性意图或借旧确认继续写。

“confirmed”是可审计的操作归属依据，不是对世界中所有编辑的证明。单次重要许可仍只批准一个效果；未来普通自主调整来自P01持续清单授权与独立的新意图，不来自扩大旧grant。

## 数据与迁移

schema37新增 `reminder_schedule_bases`：UUID id、唯一intent_id、authority、可选operation_id。与新意图同事务保存，初始无期限/人工/承诺归属也显式保存。无外部基线的本地意图不造归属证据。控制中心显示基线类型及AI执行依据。

有basis包v37，表顺序为v36基础后追加basis；没有basis的旧结构保持v34/35/36。导入校验基线、先前操作、版本顺序与连续观测，不能把observed回执改写为AI归属。旧包拒绝basis文件。迁移意图/操作仍frozen，basis仅历史证据，不恢复连接或执行权限；非空schema36升级保留所有原表。

## 验证与接续边界

证据与实际回归数见[本增量证据](../research/evidence/m3-w14-schedule-bases-2026-10-13.json)。专项覆盖连续三轮自主改期、observed不授予归属、人工期限变化与改回、人工移除、仅标题修改、明确承诺保护、迁移冻结、迟到核对不改历史、未知期限间隔、非空schema36升级、重算摘要伪造归属，以及规划后字段变化屏障。

不依靠重跑旧云端请求或修改真实正式任务取得成功；不产生Outcome或提升认知状态。原生UI/真实EventKit改期与全部人工字段保留尚待集中验收，语音期限提取和W16补偿仍缺。M3/AC-15/自然案例A仍partial，继续既定M2→M3路线。
