## 2. 三条闭环的设计走查

**A：访谈评论 → 阅读行动 → 再次表达。** 外部访谈 Source 与用户评论分开；暂定 Claim 引用户片段，明确阅读意图产生 Task。持续授权下 EventKit 创建并回读。外部完成形成 Outcome，Claim 保持暂定。再次录入限定性判断，检索旧版本与任务事实，生成新版本及限定 Relation；原猜想可回溯。不需要勾选完成时强制反思。

**B：旧灵感 → 新想法关联。** 新 ThoughtEvent 检索旧来源，正/负样本判断关联依据；候选静默出现，用户忽略不建任务、不进入对话。用户显式开启 B 后用带出处上下文讨论，新的用户表述再入历史，AI 建议保持候选。

**C：两次英语表达。** 两次原音/原句各自保存，转写与修正稿分开；ExpressionFeedback 比较具体片段，修正转写时冻结错误比较并重新判断。文本表达建议不包含未经音频后端验证的发音分数。本地英语资源不足属于待解决路由条件，不能删掉首版案例。

这三条是纸面走查，尚无产品程序运行；当前探针不覆盖端到端链。

## 4. 产品与工程边界复核

本轮没有新增需要重新确认的产品方向歧义。D01–D10、P01–P04/P06 保留；P05 数值仍待测后校准。基础 B 的文字入口是实现推荐，按回合语音/全双工深化需分别验证；不能把“文字入口”解释为取消语音优先或取消基本对话。

最低 OS、具体媒体格式、备份频率/加密、通知窗口及费用限额都是明确待定参数，没有因为模型或平台方便而擅自冻结。若测试迫使删掉首版能力、改变静默默认、自动上传音频或要求普通任务逐条批准，单独说明产品影响交用户确认。
