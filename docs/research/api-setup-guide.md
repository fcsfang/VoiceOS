# 模型 API 本地配置与使用

日期：2026-10-10。状态：用户提供配置已转换，第三方服务认证与一次结构化生成实测成功；另有超时和 HTTP 503，完整质量对照暂未完成。

## 原文件是什么

`docs/模型api 配置.md` 的内容是有效 JSON，带有 OpenCode 配置 schema。它包含服务地址、密钥、模型显示名称、限制和 build/plan 选项，适用于对应客户端；复制这份文件不会自动让 Python、VoiceOS 或系统环境获得这些设置。模型名和上下文数字也只是客户端声明，不是服务能力的实测证明。

当前实际地址是第三方兼容服务 `https://api.chiyi.cc/v1`。本轮在此服务上请求，不是直连 OpenAI。原文件已被 Git 忽略并限制为本人读写；没有删除或把密钥替换成失效内容，也没有把文件内容执行为脚本。

## 现在的配置入口

必要值已提取到项目根目录的 `.env`，权限为 0600，Git 忽略。用于技术探针的字段只有：

| 字段 | 作用 |
|---|---|
| `OPENAI_BASE_URL` | 实际服务根地址，包含 `/v1` |
| `OPENAI_API_KEY` | 此服务的本地密钥，只在请求头用于认证 |
| `VOICEOS_PROBE_MODEL` | 本地候选模型备注；本轮运行通过 `--model` 明确指定模型 |

仓库中的 `.env.example` 只有占位值。探针直接读取本地 `.env` 的键值，不需要把密钥粘贴进命令、聊天或文档，也不需要运行原来的 JSON。未来正式应用如何从系统凭据库读取另行设计，这不是生产密钥存储方案。

## 如何运行已准备的探针

在项目目录运行以下命令只检查并准备一个合成请求，不发送网络请求：

```sh
python3 scripts/probes/cloud-text-evaluation.py --model gpt-6.1-sol --limit 1
```

加 `--execute` 才发送合成文本。每模型最多十个已有样本，无工具、无音频、无个人历史、无自动重试；本轮已有结果保存在 `tmp/research/cloud-results/`，相同模型/样本的已有尝试会跳过，包括超时和错误。程序不会因为再次运行而静默重复可能已计费的请求。

```sh
python3 scripts/probes/cloud-text-evaluation.py --execute --model gpt-6.1-sol --limit 10
```

这是后续明确决定继续新样本时的入口，不表示本轮十条均已执行。发生传输错误或非 200 状态即停止该轮。不要删除未知结果来制造“首次请求”；是否重测应先记录原因、新的试验身份及费用范围。

## 已确认和未确认

- `/models` 认证成功；两项目标模型列在返回列表。
- 输入计数接口返回结果；但一次请求计数 319，生成 usage 输入为 519，存在不一致，不能把兼容服务计数当作精确预算保障。
- Sol 的一次 Responses + JSON Schema 请求成功，可解析并保留否定与条件；不能据此批准整个认知引擎。
- Luna 首次生成在 60 秒客户端等待后超时；Sol 下一样本返回 HTTP 503。已经停止进一步生成，没有切换其他代理或自动重试。
- `store=false` 是请求参数，不能证明第三方实际不保留数据；官方 OpenAI 的保留政策和价格不能自动套用。仅使用合成文本，原始音频没有上传。

真实费用、服务端模型来源和保留政策目前未核实；超时请求也不能认定零费用。详见[本轮实测报告](api-reminders-validation-2026-10-10.md)。后续先解决服务稳定性，再扩展语义测试与月度成本测量。
