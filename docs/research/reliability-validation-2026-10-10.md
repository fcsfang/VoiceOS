# VoiceOS 可靠性验证：补充报告

日期：2026-10-10。状态：第三阶段继续进行，完成三个合成数据实验与一个提醒事项探针构建；不构成真实应用验收。前一轮证据见[初步报告](technical-validation-2026-10-10.md)。

## 1. 本轮结论

| 问题 | 实际结果 | 可支持的工程结论 | 尚不能证明 |
|---|---|---|---|
| 数据库与文件分开落盘，中断后会怎样 | 7 个窗口符合预期，重跑恢复状态稳定 | 先记录意图，保存片段，再记录封存摘要，最后登记可处理状态；未封存内容不能宣称完整 | 麦克风、音频容器修复、真实睡眠、断电、磁盘耗尽 |
| 外部成功但本地没收到回执 | 模拟两套独立存储，6 种结果符合预期 | 待核对状态独立于失败；优先回读操作身份，零条/多条/外部编辑不能盲目重放 | EventKit 标记/ID 稳定性、iCloud 延迟、双进程并发 |
| 导出能否保留长期历史 | 7 类合成实体，10 项校验符合预期 | 可读结构化包和快照备份各有用途；权限、纠错和失效关系必须一起迁移 | 正式数据模型、升级迁移、加密、大文件、生产删除 |
| 原生提醒事项程序能否构建 | SwiftUI/EventKit 源码编译、应用包签名校验成功 | 当前 Mac 可继续真实接口验证 | UI 运行、系统授权、任何真实写入与回读 |

所有实验只操作临时合成数据；临时数据库实验结束清理。没有麦克风录制，没有个人提醒事项查询，没有 API 请求。本轮独立验证源码放在 `scripts/probes/`，没有建立业务核心或完整应用。

## 2. H03/H08：跨资源中断

探针：`resource-recovery.py`；[原始结果](evidence/resource-recovery-2026-10-10.json)。子进程在五个位置直接退出：意图事务提交后、合成字节片段 fsync 后、封存摘要事务后、文件重命名后、ready 事务后。另从 ready 情况分别删除或破坏文件，共七种。

- 意图后无文件：恢复为 `interrupted-empty`，不伪造录音完成。
- 存在未封存片段：恢复为 `interrupted-with-fragment`，保留片段等待检视。
- 已封存或已经重命名：校验摘要，必要时完成重命名，恢复为 `ready`，字节相同。
- 原始文件缺失或摘要不符：`quarantined`，不能送给理解层。
- 每种结果再执行一次恢复，状态保持稳定。

这模拟了本地资源协议，内容只是合成字节，未证明它是可播放音频。文件 fsync、数据库提交和重命名仍不是单一原子事务；本轮没有目录 fsync 和断电实验，不能声称具备断电保证。真实录制应保存可识别片段边界，验证容器在每个中断窗口下是否可恢复；不能仅移植此状态名就宣布可靠。

对照：只写数据库无法证明媒体已存在；只写文件会缺少处理身份。候选方式是持久意图 + 分段封存 + 校验恢复，代价是多次落盘和恢复逻辑。完整原生录音生命周期仍待 H03 验证。

## 3. H05/H09：外部未知结果与去重

探针：`external-operation-reconciliation.py`；[原始结果](evidence/external-operation-reconciliation-2026-10-10.json)。外部 SQLite 模拟器没有操作身份唯一约束，不能通过本地数据库唯一性偷换外部幂等。子进程先提交本地发送记录，再提交外部项，然后在写回本地回执之前退出。

六种恢复输入：回执丢失、查询暂不可见、外部标题已编辑、标记重复、权限撤销、外部项删除。回执丢失时通过唯一身份与快照匹配恢复确认；延迟可见先保留 unknown，返回可见后确认；外部编辑保留 conflict；多匹配保留 ambiguous；权限撤销 blocked；零匹配保留 unknown。所有核对都没有再次创建或覆盖外部项，重复核对状态稳定。

这验证实验中的决策分支，不证明真实第三方的查询语义。未知状态也不能无限卡住：正式设计还需核对期限、重查调度、用户可见解释和恢复入口；它们应在架构状态机里写清楚。本轮没有用生产外部适配器，也没有测试并发抢占。

对照：超时立即重试简单但可能重复创建；只用标题查重会混淆同名任务；采用操作记录与身份核对可减少误重放，但依赖真实外部标记的保存与查询能力，需要原生实测。

## 4. H08：备份与可迁移包

探针：`portable-snapshot.py`；[原始结果](evidence/portable-snapshot-2026-10-10.json)。合成 Source、ThoughtEvent、Claim、Revision、Task、Outcome、Relation 各一条，覆盖仅本地标记、暂定归属、未验证证据、已替代观点、任务完成、外部映射和失效关系。

SQLite 活跃连接在 WAL 下经 backup API 得到一致快照，完整性与记录对照一致。另导出版本化 JSON + manifest + 可选媒体资产，再恢复到新数据库；实体身份和全部 payload 相同。损坏记录、缺失捆绑资产、未知格式版本、路径越界和悬空引用均拒绝；不包含媒体时明确标注 reference-only，保留定位和摘要，不能声称音频已被恢复。

manifest 校验只能检测与记录摘要不符的破坏，不能抵御同时修改内容和 manifest 的攻击；未提供签名/加密。正式导入还需事务预检、重复身份策略、来源引用完整性、权限衍生链、路径/大小限制和失败清理。当前合成包 schema 只用于实验，不是已冻结的 VoiceOS 数据字典。

对照：纯数据库备份恢复方便但依赖实现；可读逻辑导出易迁移但需版本和引用校验；两者互补。外部映射恢复后应先核对，不重建已存在提醒事项。格式、压缩、加密与备份保留策略在正式设计时记录 ADR。
