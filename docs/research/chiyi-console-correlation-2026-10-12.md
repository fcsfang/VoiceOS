# Chiyi 控制台与本地 504 时序对照

日期：2026-10-12。

用户在 Chiyi API 控制台观察到，最新一条约 05:11 的请求明显慢于普通请求，且没有首字输出。该现象与本地 600 秒合成试验的时序相符：聚合请求在客户端等待约 301.22 秒后收到 HTTP 504，客户端 600 秒窗口没有到期。

## 当前可确认的结论

- 这次失败不是 VoiceOS 本地 600 秒等待窗口触发的超时。
- 请求已经到达 HTTP 服务并获得了 504 响应；因此不是本地网络调用完全没有返回。
- 约 5 分钟的固定失败时间，说明网关或其上游链路存在独立的超时边界。
- 请求使用非流式 Responses 传输。此模式下，模型生成内容不会以“首字”持续显示给控制台或客户端；首个可见响应通常要等完整响应准备好。因此“没有首字输出”与 504 一致，但不能单独证明模型没有开始生成。
- 输入规模和聚合复杂度仍是合理的诱因：本次聚合请求约 45,833 字节、64 条证据，而两次较小的提取请求分别在约 107.63 秒和 63.88 秒返回 200。但现有样本不足以证明输入大小是唯一原因。

## 边界

目前不能从控制台缺少日志或单次 504 推断：

- 模型服务一定没有执行；
- Chiyi 一定是最终超时责任方；
- 输入超过某个固定字节数就必然失败；
- 调大 VoiceOS 客户端等待窗口即可解决问题。

下一步应使用新的合成资料库做只改变证据条数/请求大小的对照，并记录同一 600 秒窗口下的请求字节数、首个响应时间和 504 时间。旧 unknown 或本次 504 不重发，也不把本次请求升级成流式重试。

证据：[600 秒本地时序](evidence/long-text-wait600-2026-10-12.json)、[长文字等待窗口试验](../engineering/long-text-wait-window.md)。
