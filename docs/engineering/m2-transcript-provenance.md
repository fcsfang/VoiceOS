# M2 逐字稿来源与更正基础

日期：2026-10-10。M1 基线为 `8afddd9`；M2 基础由用户提交 `2f6e533`，本轮补修界面初始化与迁移历史校验。此交付覆盖 W09/W11 的部分基础，不代表 M2、AC-17 或完整 MVP 通过。[脱敏证据](../research/evidence/transcript-provenance-2026-10-10.json)。

## 已实现

- 本地 Speech 结果保留实际片段时间和 Unicode scalar 文字范围；没有时间的结果明确未知。已存在的旧稿升级为第一版，未知时间不补造。
- 初次转写原稿不可被更正覆盖。更正创建独立版本与修订回执，保留原件、历史文字和版本身份；原因是识别文字更正，不是用户认知演变。
- 更正须匹配当前版本；过期编辑拒绝。相同命令同内容返回既有结果，同命令改变内容拒绝。版本、回执和当前指针在一个事务中提交。
- 更正改变文字对齐，当前版时间标为未确认，原稿的定位仍随旧版保存。当前版本检测接口可排除过期逐字稿；还没有后续认知依赖图。
- 控制中心可查看来源片段、手动发起片段回放、更正文字及查看新旧历史。首次打开更正窗口的空稿问题已修复；内容未改时不能保存。
- 数据库 schema 3；迁移包格式 2，六类实体包含逐字稿版本与修订。保留格式 1/schema 2 的空库恢复兼容；恢复校验当前指针、连续历史、原稿一致、修订关联与文字/时间范围。

## 验证与边界

21 项 Swift 核心测试通过，包括过期更正拒绝、原稿保留、历史身份迁移、Unicode 范围与时间越界；另有针对“文件摘要全部正确，但更正回执被移除”的恢复拒绝测试，目标库不会建立。

更新后的同一核心执行 26 项真实 M4A/MP4 保存及转写恢复检查，包含 20 次 SIGKILL，均通过。这是进程退出证据，不能代替睡眠、断电或真实录制实验。

一分钟授权音频实际产生 286 个 Unicode scalar 与 3 个时间片段。通过原生界面首次载入原稿、保存测试注记、打开历史，确认两版分别显示；退出后导出含媒体包并恢复，三个历史表逐字段完全一致。测试注记明确不是音频内容，不用于识别准确率评分。真实格式 1 包恢复到新核心也已核对。片段播放入口已实现，实际时间对齐与回放体验尚未人工验收。

没有把测试文字变成个人观点或提醒事项，没有上传原始音频。当前认知/行动对象、依赖冻结、上下文权限重验、旧模型回调、整理稿、英语反馈和完整闭环均未实现。因此所有顶层产品 AC 状态仍保留未完成。

## 本地上下文契约

`LocalTranscriptContext` 是已实现的临时本地快照，显式选择来源后保留 source/version、逐字稿版本、文字及片段、外部归属/未知说话人与仅本地限制。按 Unicode scalar 预算检查；超预算、重复、缺失或未转写的选定来源整体拒绝，不静默截断或略过依据。使用前再次读取当前版本/限制并核对内容摘要；保存原件也重新校验摘要，损坏会隔离。

三项新增核心测试验证：更正使旧快照失效，外部身份不变成用户观点；选择与预算拒绝不生成部分结果；篡改快照或损坏来源使重验失败。这里只能准备与检查本地输入，没有发送能力，没有持久 ContextBundle、policy/knowledge epoch、模型 job 或结果提交事务。后续云端发送与提交必须把重验整合进持久调用身份及事务，不能把一次本地检查当长期通行证。
