# M3 提醒事项读取超时与取消

日期：2026-10-10。接续[表达行动闭环](m3-expression-actions.md)，修复后台串行核对可能因原生回调不返回而永久等待的问题。未改变产品愿景、任务授权范围或数据格式。

## 行为与实现

每次 EventKit 异步读取现在有八秒的回调等待窗口。正常返回保留原有清单/标记/身份核对；超时或任务取消先结束等待状态、取消原生请求，再恢复调用方。缺结果记为 unknown，保留历史，不当完成或自动重建。超时是可调工程默认，不是系统所有原生调用都能在八秒内被强制中断的承诺。

采用 MainActor 上的单请求 CallbackWait：正常、失败、超时、取消只结束一次；同步回调兼容；重复/晚到回调忽略，不再触碰失效 EKReminder；预先取消的请求不发起新的 fetch。等待完成后清理定时任务和取消句柄，NativeReminders.reading 通过 defer 释放。写入入口也检查任务取消，但已经进入同步 save 的操作仍不能保证撤回。

Apple 的[cancelFetchRequest 文档](https://developer.apple.com/documentation/eventkit/ekeventstore/cancelfetchrequest(_:))和本机 EKEventStore.h 明确指出取消后原 completion 不会被调用。因此不能只取消原生请求、继续等待旧 continuation，必须由等待器主动结束。备选仅把 continuation 放入 TaskGroup 与 timeout 竞速，也不能保证无回调的子任务结束后组才能退出；独立进程可以隔离同步挂起，但会增加权限身份/宿主/通信代价，当前先修复可取消异步读取。

保存连接后界面立即显示“正在核对所选清单的任务”，避免仍显示旧连接暂停状态。连接停止和授权版本屏障仍负责阻断旧结果应用，不依赖取消一定成功。

## 验证与限制

74 项自动化测试通过，新增五项：同步/重复成功只返回一次；无回调超时取消，晚到结果不污染下一读；在途取消无须等待回调；预取消不启动；调度停止/恢复取消原等待后再开始下一处理，处理峰值仍为一。此前 25 项强制退出检查的 Core/保存/模型逻辑未改，本切片不新增或重跑崩溃案例。

真实 VoiceOS 应用重新连接原专用测试清单，使用新等待路径自动核对原有合成已完成任务；关联仍一项、完成版本仍 2、外部完成历史仍一条、观察仍两条，未新建任务或发模型请求。测试连接再次暂停。构建/开发签名通过，schema 10/逻辑包 9 未变；证据见[汇总](../research/evidence/reminders-read-lifecycle-2026-10-10.json)。

没有人为挂起真实 EventKit 服务或撤销系统权限；故障/取消测试为受控回调替身。MainActor 被同步系统调用堵塞时定时任务也无法立即执行，八秒不覆盖日历刷新/同步保存的硬挂起。真实睡眠/唤醒、离线/iCloud 延迟和生产沙盒继续验证。不能把正常原生读取加模拟超时当成全部系统故障验收。
