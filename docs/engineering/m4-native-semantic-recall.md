# M4：原生本地语义召回

日期：2026-10-11。状态：开发切片实现并验证，完整产品验收未通过。技术取舍见[ADR-011](../adr/011-native-semantic-recall.md)。

控制中心“查找历史文字”新增“按意思找原文（本机）”。含模型的构建可在当前原文中跨措辞找八个候选，再复用上阶段的范围准备、文本模型相关性判断和出处返回。仅本地资料可以参与本机召回；云端判断仍需要查询与每份选中原文的文本授权。召回不联网、不产生关系/观点/任务，也不发通知。

## 模型与原文边界

固定 BGE-small-zh-v1.5 revision，通过离线转换保留 float32/CLS 表示，在 Swift/CoreML CPU 中归一化；分词为该词表实际配置的区分大小写 BertNormalizer/WordPiece，不擅自小写或去重音。每个编译文件和词表按长度/SHA-256 校验；超范围路径、链接、缺失、变动或未列入的编译文件拒绝加载。应用本身不自动下载。模型接口检查输入名字和输出维度。

语义切片按来源片段分成 256 标量窗口、96 重叠，保持原文范围与完整出处；旧关键词路径仍为 800/512。端口通过显式窗口契约请求切片，非法窗口在原文交付端口前被拒绝。没有按先后位置截断资料库，超过一万片段明确失败。源内容按当前文字/政策版本读入，返回与打开时重新核验。

模型缓存仅为可重建内存向量，不写入核心库或迁移包；固定模型实例按文字摘要复用，查询结束清理非当前内容，取消过程中也限制容量。千条库首次召回约 3.1 秒、后续约 0.35 秒，是本机合成测量，不是长期体验承诺。

## 实测

- 136 项测试通过，新增六项分词边界及两项真实存储窗口检查。原生模型另做实际文件/推理验证，未将约 95 MB 权重加入 Git 或单元测试依赖。
- 六个原生分词/向量对照通过，覆盖中文、英文大小写/重音、特殊标记、emoji、控制字符和 256 字长文；原生向量与源模型余弦均超过 0.99999。
- v2：24 原文/24 问题，v3：16 原文/16 问题，全部标注相关原文进入前八。1000 原文/1011 片段容量库的五个相关目标也全部进入前八。容量库是 32 类重复模板及编号变化，不能当作千个独立质量样本。无相关问题仍会出现弱候选，需独立判断，召回率不是最终准确率。
- v2 20/24 查询的前八顺序与 Python 研究输出完全相同，匹配项最大分数差约 5.3e-7；其余同分填充片段改变弱候选顺序，标注目标全部保留。未修改样本标签或以转换结果调阈值。
- 四项真实资产异常均在新测试库创建前阻断：精度身份修改、权重字节损坏、未列出的编译文件及逃逸链接。
- 原生界面截图核对了按意思入口、长文末尾候选、仅本地标记和出处打开；在同一模型实例更正该合成长文，再次查询不返回旧摘录。查询测试没有发送云端。
- 单次额外合成链路：本地召回八个片段 → 严格相关性驱动 → 正确选择预期记忆练习原文，905 标量输入文本，1769/66 token。未产生 Claim/Action 或外部写入；回执导出/恢复通过，八条输入保留，恢复后 frozen。费用金额仍未知。
- 最终含模型应用构建/签名校验通过，模型资源约 94,940,860 字节；MIT 来源许可随构建打包。23 个愿景文件未改，AGENTS.md 保持四条。

证据：[摘要](../research/evidence/native-bge-2026-10-11.json)。忽略目录中的转换日志、v2/v3/容量结果及真实链路记录保留用于复核。UI 测试对 v2 合成库做了一次更正，报告保留的是更正前的质量测量；重现评估应创建全新根，不能对这个已修改库重跑原标签评分。

## 构建与复现

开发转换使用独立 Python 3.12 环境，torch 2.7.0、transformers 4.57.1、safetensors 0.6.2、coremltools 9.0；只读固定原始模型，核验六个固定源文件摘要，禁用远程代码和在线模型加载。脚本：`scripts/probes/convert-bge-coreml.py <原始模型目录> <全新输出>`。首次 Python 3.14 转换失败；3.12 的证书配置使用已有可信 CA，未关闭 HTTPS 校验。

含本地模型：`python3 scripts/app/build.py --semantic-model runtime/bge-coreml-2026-10-11`。普通 `build.py` 不包含模型，语义开关不可用，关键词仍可用；不会沿用上次打包的模型产生隐含依赖。离线模型文件位于 runtime，未在仓库中；需依研究脚本取得固定文件再转换。应用运行不需要这些 Python 环境。

`voiceos-check bge-eval <模型目录> <parity.json> <合成夹具> <全新测试根>` 可复现实测；只有明确追加 `--cloud-config <本地配置>` 才执行一次付费合成相关性调用。两种路径都只创建新的合成库，不打开个人库。

来源：[BAAI 模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5)说明 CLS/查询指令及分数分布；[Apple 转换指南](https://apple.github.io/coremltools/docs-guides/source/convert-pytorch-workflow.html)说明 PyTorch 捕获及 ML Program 转换。实际接口、大小、性能与对照来自本机记录，未由文档推定。
