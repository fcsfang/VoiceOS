# 长文字等待窗口试验

日期：2026-10-12。用户明确要求调大等待窗口测试；长文本是必需能力，不缩减范围。当前已授权文本服务为api.chiyi.cc/v1。

## 变更

旧v2/v3每请求120秒，URLSession资源绝对时限也为120秒，因此较慢的正常生成会被客户端中止。原结果只能叫unknown，不能据此证明服务不可用。

新增显式600秒候选，客户端传输上限相应从180秒扩大到600秒；普通请求仍60秒，旧长请求仍120秒。每个端口只允许120或600，600的prompt/schema身份带wait600后缀，新批次固定这一窗口，旧批次不升级。聚合证据预算仍32000，分段/输出token和原话门槛保持；等待扩大不增加工具或重试。

传输诊断仅记录窗口、请求/响应字节、HTTP状态、响应头/首正文字符/总耗时与URLError数字类别，无URL、响应头、凭证或正文；成功和失败均记录。收到响应头并不等于正文已经开始，首次正文时间单独测量。时钟为客户端测量，不能分解服务端排队和生成时间。

## 本次试验

`voiceos-check segment-wait-cloud-fixture <new-runtime-root> <config> --authorize-synthetic-text` 创建5541字符新合成工程文本及独立资料库（两段3962/1579字符），使用v2提取/聚合和600秒窗口，避免与精简协议同时变化。没有个人音频/文字发送、麦克风或提醒事项写入；正文明确不是用户实际承诺。旧unknown来源不重发。

17项直接相关检查通过，包括两个阶段600秒请求、身份漂移拒绝、超界配置拒绝、v2/v3既有协议、配置加载与预算；不是完整回归或自然语义验收。构建通过，日常应用保持此前版本和配置。本次完整报告与分段状态以独立库为准，不把在途预留当成功。

## 解释边界

成功响应超过120秒可证明旧窗口会截断这一请求；不能凭一次成功推出Chiyi整体稳定。600秒仍超时只说明本次更长窗口没有得到完整回执，不能断言服务端未执行或没有能力。结构拒绝/输出不足与网络超时分开记录；费用未知，没有失败自动重试。

## 取舍

按用户此次授权先延长等待，不同时更换服务、模型、分段算法或输出预算，这能观察旧窗口是否截断较慢回执。600秒是有限试验上限，不是已确定的产品时延目标；代价是未知请求的判定更晚。备选为流式响应或服务端异步查询，但需实际兼容证据与独立协议身份；自动重试会重复费用/结果，仍不采用。生产默认是否调大在实测后决定。

## 最终结果

5541字符合成稿的两段提取通过，HTTP200；响应头/首正文/完整体约107.54/107.54/107.63秒及63.40/63.40/63.88秒。聚合在301.22秒收到HTTP504，请求45833字节；返回体4491字节未展示或入公开证据，认知提交和外写均0，完整性通过。全链约473秒。

客户端600秒没有用完，最终是HTTP失败，不是本地URLError超时。旧120秒会更早中止，掩盖约5分钟后的网关或上游504；不能据此推出整个服务不能处理长文本，也不能推断504必定由Chiyi自身而非上游产生。两段成功均在120秒内；没有成功完成且超过120秒的模型结果，因此不能宣称调大窗口已修复链路。传输诊断的completed仅表示HTTP响应体完整读完，不代表HTTP200或模型成功。

本次只发出2次提取与1次聚合，没有重试。等待窗口仍是显式候选，未切换日常应用默认。下一可验证方向是服务的流式或异步接口能否避免非流式约5分钟超时；需新独立样本与兼容证据，旧unknown或本次504不重发。证据：[600秒实测](../research/evidence/long-text-wait600-2026-10-12.json)。

## 精简聚合对照

随后使用新的合成资料库、相同5541字符文本、相同600秒窗口，只启用 v3 精简证据投影。两个提取请求正常完成，约56.86秒和53.41秒；聚合请求从完整账本投影约45,833字节降至约31,746字节，仍在约300.76秒收到HTTP504。该对照排除了“几千个字符或当前请求体大小单独导致失败”的解释；当前更可能是非流式聚合请求的固定网关/上游处理边界。证据：[精简聚合600秒对照](../research/evidence/long-text-compact-wait600-2026-10-12.json)。
