# M4：控制中心相关性判断

日期：2026-10-11。状态：已实现并完成原生界面合成验证；跨措辞自动召回和完整 M4 尚未完成。

## 使用路径

工具栏“查找历史文字”先在本机用关键词查找当前原文。用户勾选最多八份候选，填写想找回的问题，点击“准备所选原文”检查完整文字与文本授权；准备本身不调用模型。“用文本模型判断”才将问题与所选原文发给已配置的文本模型，返回最多三份相关原文或空结果。界面显示发送范围、4000 Unicode 标量预算、仅本地限制和用量。

本轮选择这一渐进接入，而非使用此前质量不够的系统语义召回，或将整个历史库送入云端。代价是用户需要先查找和选定候选；判断结果只覆盖所选范围。它不是全库语义搜索，不创建关联、观点、行动或通知。后续经过验证的本地召回可复用同一个候选、出处与持久调用契约，无须迁移业务身份。

“核对相关原文”先检查来源版本，再关闭查询页并定位到来源详情。当前引用与用户原文/外部原文、文本权限一起呈现；来源片段与版本历史仍由既有详情页提供。相关不等于赞同、用户认可或事实验证。来源文本授权说明同步覆盖文字理解与相关性判断，原始音视频未进入这条流程。

## 生命周期

`RelevanceQueryCoordinator` 管理当前界面查询：关键词、问题、候选范围、模型配置变化及窗口关闭会取消旧查询并清理结果。发送后的持久调用留在核心存储；停止等待不能宣称撤销已发生的服务处理或费用。晚到回调不能覆盖新问题、恢复已消费的发送按钮或写回界面结果。

准备时生成 queryID 与有界快照；完成后仍保留完整输入用于检查，包括模型未选中的原文和空结果的输入。原文更正/文本授权变化会使整个结果失效，不能只校验返回的 ID。同一已执行快照被消费，错误和未知结果也不会由界面自动重发；再次准备是用户主动发起的新查询。重开不自动恢复界面请求。

## 验证结果

- 128 项测试通过，零失败。新增协调器测试覆盖晚到取消回调、新旧查询隔离、已消费快照、空结果的完整输入失效，以及仅本地准备不登记调用。
- 原生界面完成关键词查询三份合成原文、选择范围、准备、实际模型判断和出处返回；模型只选中预期记忆练习原文，界面显示 604 输入/70 输出 token。截图实际检查了排版和按钮状态。
- 将该来源改为仅本地后再次准备，界面阻断发送；关键词改动清除候选，问题改动使旧准备失效。测试过程中总共只有一次新的云端调用。
- 关闭后两次读取一致；调用历史共有两条，其中一条来自测试库恢复的上阶段历史。来源权限撤回后，两条 completed 历史均 frozen，六条输入保留，没有 Claim/Action/提醒事项写入。新导出及空库恢复通过。
- 最终应用重新构建并通过签名校验，重开后核对新版说明；23 个愿景原始文件未改变，AGENTS.md 仍为四条。

## 下一步

接入已完成初步质量评估的本地语义召回，先确定模型运行、资产校验、版本固定与投影重建机制，再复用当前相关性判断。必须测试长文切片、近期/旧历史、出处更正、权限变化及资源不可用时的行为。真实长期历史质量、自动关系反馈、麦克风/睡眠及全部产品 AC 尚未关闭；本阶段没有新增产品决策或用户待确认问题。
