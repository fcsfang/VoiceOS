# M3 增量：控制中心恢复与独立资料库

日期：2026-10-10。开发预览新增迁移菜单操作，沿用已经验证的空库恢复契约，不改产品方向或迁移格式。

## 用户流程

工具栏迁移菜单提供“从迁移包恢复…”：选择迁移包文件夹，查看版本、资料数量与原件省略情况，选择上级位置并输入新资料库文件夹名称，再“校验并恢复”。元数据预览不是完整性通过证明；恢复时仍执行文件摘要、关系、原件与数据库校验。

当前资料库保留。已有目标直接拒绝，包内位置也拒绝。成功后显示恢复结果，可“打开恢复的资料库”进入独立窗口。窗口标题带资料库名，记录与处理均绑定该库。新库保留历史但无本机提醒事项连接授权；若要连接，必须在该窗口明确选择清单。

重启后可用“打开已有资料库…”选择恢复库继续使用，无需再次恢复。只接受包含 voiceos.sqlite 的目录；实际加载仍检查格式、单写者锁和恢复状态。不改变主窗口的默认库位置。全局导入快捷键按当前聚焦窗口选择处理器，防止多窗口导入到错误资料库。

## 实现与取舍

恢复入口调用现有 `VoiceOSStore.restorePackage`，没有另一套降低校验强度的 UI 导入实现。预览读取不超过 1 MiB 的 manifest，拒绝符号链接、未知格式和非法计数；包全体校验仍由恢复负责。迁移版本仍为 v10/schema 11。

采用新目录与独立窗口，避免恢复覆盖当前库或关闭正在工作的引擎。另一方案是覆盖/切换当前库，但需要处理在途模型调用、单写者锁和外部操作，当前不采用。副作用是暂不自动替换默认库；用户通过已有库入口打开。库合并、删除和云同步仍未实现。

打开已有库是正常加载；已有库自己的持续连接授权仍按其历史生效。这个规则不同于迁移新库，后者不带授权。此切片没有扩大授权，也没有创建外部任务。

## 验证

82 项自动化测试通过，包括两项新预览检查：结构化包准确报告省略原件且不创建库；未知版本与符号链接清单被拒绝。已有恢复失败、字段关系、恢复目标保护及迁移历史测试仍通过。

实际界面路径使用合成资料：

- 损坏 sources.jsonl 的包显示具体损坏错误，目标没有建立。
- 把目标指定为当前 feedback-ui-v1，显示已有目标拒绝，当前库不被覆盖。
- 完整包恢复到 restore-ui-actual-v1；成功后新窗口能读取反馈和父行动关联。
- 在新窗口保存一条合成表达，原库仍三条、新库四条，两库调用历史各一条、外部授权均空。
- 退出进程并重启，通过“打开已有资料库…”重新打开新库，四条记录仍可见。

测试中发现菜单启动的已有库选择器未稳定显示，改为绑定当前窗口的系统选择面板后，重启实测通过。不能用构建成功代替实际界面证据。
