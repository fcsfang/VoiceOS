# M1 文件输入切片实施记录

日期：2026-10-10。状态：开发预览已实现并实测；M1 整体未完成。依据：[路线图](../planning/implementation-roadmap.md)、[PRD](../product/prd.md)、[数据模型](../architecture/data-model.md)。操作与复现见[开发指南](development-guide.md)。

## 交付范围

交付可构建、可打开的单 Mac 原生应用、可复用 Swift Core 和原生平台适配器。固定开发 bundle ID `local.voiceos.app`，数据独立于既有提醒事项探针。文件导入、可靠原件、持久转写 job、独立窗口/宿主、本地中文逐字稿、关键词查询、结构化/可选媒体导出及开发工具空库恢复已经接入同一核心。

Source/Asset/Job/Transcript 具有独立 UUID；Source 有固定版本身份、外部归属/未知说话人、时区和仅本机处理字段。同一 command_id 不重复建记录，同 ID 换内容拒绝；新命令即使文件相同也保留新记录。schema 明确版本化，本轮 schema 1 → 2 原子升级已对既有开发资料库执行，新增无原件的 reference_only 状态。

这是数据模型的输入子集：尚无完整 Object/ObjectVersion、片段定位、修订/冻结/删除屏障、来源闭包或外部 Operation。不得由这四张表推断 W05 全部完成。

## 保存与执行契约

1. 先持久化导入意图与已知文件长度/hash，再创建新临时副本；临时路径保留媒体扩展名。
2. 复制流同步，摘要/长度与原件一致并能完整解码音轨后 sealed；改名到独立受管 assets，同步两侧目录。
3. Source.saved、Asset 封存元数据和唯一首个转写 job 在同一 SQLite 事务中提交。
4. 启动恢复只依赖受管副本与持久元数据。完整 known-length/hash 输入可继续封存；没有或不足副本为 interrupted，已封存损坏/缺失/不能解码为 quarantined，job 停止。
5. 单写者进程锁覆盖资料库生命周期；job 用持久 running 状态/attempt/lease token，进程退出后重置未结束工作。结果提交检查当前输入版本、来源状态和 lease；没有跨进程租约超时抢占。
6. 原件完整性在转写前后和用户打开原件时复核。空转写作为实际空结果保存；已完成 job 不重复覆盖逐字稿。

第一次真实导入暴露 `.part` 扩展名导致系统拒绝识别容器的问题，已修复为 `.part.<媒体扩展名>`，重新验证有效。没有用绕过媒体校验把错误窗口标为成功。

## 实测与边界

| 检查 | 结果 | 说明 |
|---|---|---|
| 核心自动测试 | 15/15 通过 | 独立可控夹具，覆盖身份、保存、损坏、重试、空文字、单写者、Unicode/NUL 和迁移边界 |
| 同一核心的真实媒体进程故障 | 26/26 通过 | 两份已授权素材各 13 案例，20 次真实 SIGKILL；最终 v2 汇总见[证据](../research/evidence/app-input-2026-10-10.json) |
| M4A 一分钟与 MP4 26.9 秒 | 都保存成功 | 完整音轨解码；本地逐字稿分别 286 Unicode 标量/空文本，没有人工金标准质量分 |
| 原生界面 | 导入、来源/状态、全文、视频空结果、搜索、导出通过 | 实际文件选择导入一次，新记录独立；正常退出、回读及恢复库打开成功；关窗中继续转写/睡眠仍需专项测试 |
| 迁移包 | 结构化/完整媒体及界面导出的结构化包均能空库恢复 | 身份/文字不变；省略原件不可播放；待运行 job 暂停；损坏/越界/链接/覆盖拒绝 |
| 安装构建 | 本地构建及临时签名严格校验通过 | 非正式签名/公证/分发验证；无跨机支持承诺 |

故障用例包括 intent、首块复制、全量复制、sealed、文件改名、保存事务未提交/已提交、受管原件损坏/缺失、无输入路径依赖的重开、job 已领取、逐字稿事务未提交/已提交。重复重开后记录/单个 job/单个逐字稿不增殖，SQLite 完整性与外键检查通过。无输入路径依赖测试不删除真实用户原文件；独立单位夹具另验证物理移除导入文件后仍能读受管副本。

全部媒体/逐字稿/实际来源路径只留 runtime 私有目录；未上传音频/个人文字，未访问麦克风、提醒事项或下载模型。界面截图已现场查看，含逐字稿，不作为公开证据入库。
