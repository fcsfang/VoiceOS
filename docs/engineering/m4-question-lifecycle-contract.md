# 可追溯的问题生命周期契约

2026-10-11；纯输入校验已实现，持久状态与模型分类待接入；依据愿景§5.3/5.6/5.7、PRD-COG-01/PRD-FEED-01和数据模型Question草案。不新增必须审阅或回顾的任务，不把AI关联当问题解决证据。

## 身份与归属

问题是有版本的认知对象，归属、认可、证据、生命周期和有效性分别保存。个人问题自动提取后保持用户暂定身份；AI提出的后续问题始终是AI候选。现有claims没有内容类型，不凭问号、句尾或sameQuestion关系回填旧记录，也不把全部claims默认称为问题。

优先为新理解产物加入明确的内容类型和连续原话证据；一个明确的问题连接原claim身份及提取/审阅版本。旧模型响应没有类型时保持unclassified，不重发旧理解、不重新生成原claim/action。类型升级需要新的提示/Schema版本，旧包仍按原契约恢复。

问题保存自己的ID及不可变历史。源claim或逐字稿纠错使旧问题依据冻结，不自动标成用户改变兴趣；内容更正和重新提出的关系明确留史。重放同一次类型提取不能生成第二个问题；相同字面文字的不同真实表达不按文本摘要强行合并。

## 状态及证据

沿用模型草案open/exploring/resolved/closed，默认open在界面称“尚未登记解决依据”，只描述VoiceOS记录，不断言现实中一直未解决。

- open：已记录问题，尚无可接纳的解决事件。
- exploring：存在明确继续研究的表达/操作；不是任务进行中状态的别名。
- resolved：有明确记录的解决/答案依据和发起者；用户报告解决不等于答案客观验证通过。
- closed：明确停止追踪；不是答案成立、任务取消或数据删除。

显式用户操作可改变状态；自然语言的自动转移只接纳明确个人表达及问题身份，模糊推测保留为AI候选。首个技术切片先做显式转移，不开放AI仅凭相似度/沉默/任务完成自动解决。没有答案依据的resolved拒绝；closed也需可追溯原因。重新打开需明确原因，不因新相似记录自动复活。

每次状态变更比较expectedVersion、记录commandID、前后版本、发起者、原因和依据。依据原文及来源/逐字稿/策略版本在准备、提交和展示时重验。版本冲突或晚到纠错/撤权拒收；保留已有记录，不悄悄改成新状态。

## 静默关联

只把仍有效的个人open/exploring问题作为“尚未登记解决依据”反馈；AI候选单独标注。跨时间关联需要具体问题ID/版本、当前原话、历史原话和为何相关，不能从主题相关推断状态。已解决或关闭的问题仍能在历史中核对，不作为未解决问题催促。

忽略一条反馈只影响该反馈；减少或暂停只影响呈现/派发，不关闭问题、不取消目标。源问题或答案依据冻结时显示历史，暂不宣称当前已解决或未解决。关联不是派生依赖的充分证据；真正解决依据才进入问题状态依赖闭包。

## 技术选择与步骤

备选把问题状态塞进claims.review_state或evidence_state会混淆认可/事实验证与解决记录，排除。备选完全独立问题文本会重复身份并失去原理解历史，排除。选择独立问题记录连接claim及其版本，复用原出处与归属，独立状态修订表保存解决依据。

先实现纯输入快照/转移校验；再建问题与修订表、schema/包迁移和原子故障恢复；然后扩展单次理解Schema使新产物携带类型，旧产物保持unclassified；最后接来源页和按问题版本静默反馈。每一步只声明对应证据；不把纯快照、标点猜测或合成分类当完整问题能力。

回归至少覆盖用户/AI身份、伪引文、源claim审阅变化、未选依据变更、解决无证据、closed不等于resolved、重开不重复、并发版本冲突、状态和答案依据纠错冻结、篡改包拒绝以及旧未分类历史保持。自然质量另用真实个人问答验证。

## 输入基础证据

QuestionSeedSnapshot读取既有claim、审阅版本、连续原话、全部相关来源及权限版本，不写入问题或新认知。重复预览ID不同但摘要相同；AI候选仍为AI。QuestionTransitionSnapshot校验前后状态、正版本、原因和答案依据；原提问自身不能作为新增答案。准备及重验不会调用模型、改变认可/证据或关闭问题，也尚不校验数据库中实际问题状态的并发版本；这一约束留给持久执行。
