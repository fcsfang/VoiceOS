# 录制请求的长文字路由

日期：2026-10-12。路线归属：W07/W08/W09/W10–W12，关联复用 W15/W18。产品依据仍为既有明确“录制并处理文字”，不增加原始音频上传权限。

## 实现契约

- schema31 增加 recording_segment_plans。录制前与来源、文字授权、处理请求同事务固定片段提取和整篇聚合端口，限定原认知服务、模型与目的地。旧请求没有计划时，长文字进入 blocked，不补授权限。
- 原始本地逐字稿不超过4000 Unicode scalars 走原个人文字队列；超过时创建持久分段批次。仅原始版本1且授权/配置匹配时自动入队，更正后需另行明确处理。
- 批次命令固定为 record-segment:<requestID>。批次已提交、请求未关联的恢复间隙可复用原批次；取消同样查找该批次，不能留下仍可执行的孤儿请求。
- 片段、整篇认知沿用已知回执；认知提交后继续完整来源的授权历史关联，沿用8000字符预算。关联阶段结果落盘后不因别的录制重新扫描重发；超预算等结果保留已提交认知并显示部分完成。
- 取消会阻止尚未发送的关联，冻结在途关联；迟到用量保留，结果不驱动后续实体。已交付认知/行动仍保留历史，停止处理不冒充撤销已执行外部任务。
- 原生自动执行仅扫描明确录制请求，普通录制不自动理解。界面显示无候选、预算超限、暂停等关联结果，已提交认知后仍可停止待完成的关联；录制入队先刷新界面再发送。父批次仍 queued 等持久状态；请求 enqueued 仅表示已路由，不表示完整闭环完成。
- 有录制分段计划的导出使用 PortablePackage v31/schema31；恢复后沿用原请求和派生记录冻结规则，不自动云端或外写。其余数据包沿用按实体选择的旧格式。

## 选择与取舍

采用预先固定可选计划，复用短文字/分段两条现有执行路径。拒绝在转写后为旧请求悄悄增加计划；拒绝直接放宽短文字模型预算。代价是旧长录制需要明确重新处理，长关联超过8000字符仍有工程限制。整篇无损路由与关联预算不同，不能截断原文假装全篇处理。
