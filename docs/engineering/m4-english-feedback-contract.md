# M4 英文表达反馈契约

2026-10-11。产品依据：愿景§4.5/案例C、PRD-ENG-01及AC-19。原句、AI表达建议和练习间比较分开；后续可参考旧反馈，纠错后旧反馈不能作为当前依据。这里选择实现有出处的文本基础，不改变语音优先或添加新的产品审批规则。

首个切片准备一个当前个人练习及最多两份明确选定的先前个人练习；保存全部选定文字、角色和版本，超预算拒绝，不默默裁剪。英文练习用途由调用者明确指定，不用英文词比例猜测用户意图；中英混合技术讲解也保留原样。第三方节目和AI文字不能冒充个人练习。选择文字并不授予音频上传。

建议分为语法、表达组织、可复用句型。每条须引用本次练习中的原始片段，建议措辞及解释与原句分开；转写可能有误的建议标记possibleTranscriptIssue，不当成确定的口语错误。比较必须同时引用本次与明确选定旧练习的文字，并连接本次建议；相似问题或表达变化只是AI文本判断，不证明学习进步/熟练度。无音频评估字段、分数、行动或个人认知认可。

Core准备/重验会查实际当前来源与逐字稿；云端目的地逐份检查文本授权，返回后的更正/撤销使输入失效。纯提案校验检查角色/版本/片段范围/精确引文/预算/引用索引，不能证明语义建议正确。真实模型必须持久预留单次尝试并原子保存反馈，才可展示为已保存历史；当前已完成独立 `english_feedback_attempts` 记录、完成/未知终态和重复输入幂等，已接入控制中心入口；仍需真实英文录音与成功云端请求验证自然质量。应用隔离启动已验证 schema20 初始化，证据见 [启动探针](../research/evidence/english-ui-startup-2026-10-11.json)。

工程选择独立反馈类型：直接复用普通Claim会把语法建议混入个人认知和行动提取；独立类型可保留原句/建议/比较身份，不污染任务与证据状态。复用LocalTranscriptContext和现有权限/版本屏障，避免另建原件或复制逐字稿。已完成 schema 19→20 迁移；新导出包为 v19/schema20，v1–v18 包仍按旧表集合恢复。

接续顺序：输入/提案测试 → 持久单次反馈与旧反馈身份 → 文本驱动/真实小规模质量 → 控制中心英文入口/本地语言路由 → 两次实际练习与纠错迁移。自然英文录音、英语模型是否已安装及AC-19暂未验证；原句文字反馈不替代音频发音评估。

## 文本模型端口增量

`ResponsesEnglishPracticePort` 已接入 Core：单次 Responses POST、`store=false`、无音频/工具/重试，严格 JSON Schema 与用量保留；返回后再次执行原句、版本、角色、比较索引和重复项校验。独立记录已持久化并纳入迁移，265 项全套测试通过；尚未执行成功的真实英文云端调用，因此不宣称英语质量或 AC-19 完成。

英文端口现在纳入 `LocalTextModel.Suite`，配置文件只读取一次，五个文本端口全部成功校验后才对应用发布；也可单独通过 `loadEnglish` 做配置检查。配置测试覆盖 `.env` 与 OpenCode 风格 JSON；全套测试结果以当前构建为准。
