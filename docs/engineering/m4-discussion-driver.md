# M4 实际文本讨论驱动

2026-10-11，W17 第二切片的云端文本适配。使用用户已有本地配置，模型保持 gpt-6.1-sol；不读取 Codex 登录凭据，不切换订阅接口，不上传音频。

## 实现

ResponsesDiscussionPort 共用既有 HTTPS 白名单、凭据检查及禁止重定向的直接传输。一次 POST，无自动重试；store:false、truncation:disabled、reasoning:low、输出上限2048tokens、60秒超时、请求字节上限160000。这些是开发选择，可经质量/费用评估调整。

请求先提供去除文件名、路径、时间和音频定位的来源目录，之后按顺序提供 user 个人回合引用与 assistant 已接纳讨论段落。来源文字只出现一次；入口来源身份、否定和条件保持原文。每轮独立重建应用可见历史，未宣称复用服务端会话、加密推理或原生 Responses reasoning/phase 连续状态。备选是携带完整供应商输出项或使用托管会话，但会引入供应商状态、额外隐私/预算与迁移复杂度；以后按质量证据评估。

严格 text.format JSON schema；解析再检查根、段落、引用的确切字段、身份和逐字引文。拒绝、未完成、工具调用、错误引用和格式错误不提交回复，保留已知用量；错误正文和凭据不进入公开错误。复用上一切片的持久登记、同轮防重发和晚到屏障。

接口依据为官方[结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)及[会话状态](https://developers.openai.com/api/docs/guides/conversation-state)。官方示例说明手动提供历史的接口形式；实际第三方兼容服务能力以本次终态结果为准，不能由目录推断。

## 实测与限制

190项测试通过，0失败、0跳过，新增6项驱动测试。合成历史包含尚未验证的压缩猜想、未决定行动以及被引用的创建提醒指令；两次真实调用均 completed，各3段回复。第一轮保留原话和不确定性；第二轮延续先前四格对照并说明混杂因素，没有把用户追问当认可或执行指令。人工针对性审阅通过，不代表全面对话质量验收。

用量：第一轮输入748/输出568；第二轮输入1556/输出503 tokens。仅保存服务返回用量，实际账单未知。没有麦克风、音频上传、观点候选、行动或 EventKit 外写。迁移后两轮回复身份/用量保留且 frozen；含语义资源签名构建通过。[非内容证据](../research/evidence/discussion-driver-2026-10-11.json)。

独立夹具 `voiceos-check discussion-cloud-fixture <全新测试目录> <本地配置文件>` 最多执行两轮合成请求，仅用于已授权质量测试，不能指向个人库或重复已有目录。未知或拒绝调用不会重发。
