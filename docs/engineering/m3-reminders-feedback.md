# M3 提醒事项创建、回读与完成反馈

日期：2026-10-10。接续[本地行动与机会池](m2-actions-opportunity.md)，落实 PRD-ACT-03/04、PRD-REL-02/03 和 PRD-CTRL-01 的部分要求。已打通明确本地任务→Apple 提醒事项创建→外部完成回读→独立状态历史这一切片；尚不宣称完整自主规划、认知—行动—反馈 MVP 或全部产品验收完成。

## 使用与行为

控制中心工具栏提供“连接提醒事项…”，请求当前 VoiceOS 应用身份的系统权限并列出可写清单名称。选定清单前不查询任务；清单选择不会发送任务。系统全量权限不等于应用操作范围。每次启动需显式重新选择清单，当前没有保存的持续连接配置或自动扫描。

只有当前有效、待跟进的用户明确任务可发送；机会、AI 建议、拒绝/冻结认知及旧行动版本均不可创建。任何引用来源为仅本地时，任务标题/备注也不能外发。界面显示目标清单和本地限制，Core 在写前再次核对。备注仅保存 VoiceOS 操作标记，未设置期限、优先级、闹钟或原始资料内容。

创建前可靠保存 reminder_links 尝试；保存返回后仍回读唯一匹配，不能直接把 API 返回当同步成功。每个行动身份至多一次创建尝试，之后调用发送入口也仅回读原清单，不换清单新建。无匹配记为 missing，多匹配或标记更改记为 conflict，读取/保存异常记为 unknown；都不会自动重建或改写外部任务。

外部标题改动保留，展示在本地标题旁，不把标题当身份、不覆盖任一标题。有效、尚无本地状态修改的任务从外部唯一关联项读到完成时，原子追加 actor=external 的行动版本和回读记录。重复回读不再推进状态。完成不会认可或验证观点；冻结行动仅保留外部完成观察，不推进当前行动。

本地状态与外部状态冲突时保留双方，不自动撤销本地完成或覆盖外部编辑。外部缺项不当完成、不自动恢复。当前只实现创建和外部完成的回流，本地完成、重开、暂不跟进、改期及取消均不向外同步。用户应从详情的外部回读状态判断外部事实，不能把本地“已完成”当外部已完成。

## 实现与技术取舍

采用同应用 VoiceOSPlatform.NativeReminders → EventKit，Core 仅依赖 RemindersPort。备选独立桥和 UI 自动化会增加权限身份及故障边界，保留 [ADR-004](../adr/004-reminders-adapter.md) 的原生推荐；UI 自动化只用于本次用户授权的合成验证，产品执行依赖 EventKit。

EventKit 对象留在 MainActor，逐次重新取得目标清单，fetch 谓词限定该清单，结果再核对清单 ID。只返回匹配本操作标记/已绑定 ID 的快照，不保存同清单其他任务。读取之间不保留旧 EKReminder，也不使用默认清单兜底。实际调用参考 Apple 的[权限接口](https://developer.apple.com/documentation/eventkit/accessing-the-event-store)和[读取接口](https://developer.apple.com/documentation/eventkit/retrieving-events-and-reminders)。本地开发包增加提醒事项使用说明，未启用生产沙盒签名或承诺发布权限行为。

schema 8 增加 reminder_links、reminder_observations，同时升级 action_revisions.actor 为 user/external，旧行原样保留。迁移包格式 7/schema 8，共十六类实体，仍支持旧格式 1–6。关联保留内部行动/版本、清单 ID、唯一操作标记、期望标题、外部 ID 和尝试状态；观察记录追加序号、外部标题/完成、标记有效性、反馈版本和时间。单调序号保证导出按 UUID 排序、恢复改变 SQLite rowid 后也能取得真实最新观察。

尝试持久化不跨 await；单 Store actor 和活跃关联防止同进程重入，启动将 reserved 转 unknown。反馈、回读观察和关联状态在同一个无 await 事务提交。恢复核验版本、标记身份、回读连续性、linked 的唯一观察依据及每条外部完成历史的唯一回读来源；文件摘要正确也不能掩盖缺失反馈证据。

选择先实现一次尝试与保守回读，而非立即引入完整 outbox 重试调度，降低重复创建风险；代价是即使外部调用前失败也不自动重试，当前需保留未知状态并核对。新建同文案的新行动是新意图，可产生新外部任务，不能把新身份当旧任务重试方案。

不存在本地数据库与 EventKit 的分布式事务或原子权限 CAS。发送前检查能阻止尚未发出的动作；已经开始的保存不能因后来权限收紧而保证撤回。此时冻结依赖、保留观察、不自动删除或推进旧认知。并不承诺外部 exactly-once 或跨设备永久 ID；标记被编辑、清单移除、同步延迟需核对。

## 验证与限制

- 59 项核心测试通过：包含丢保存回执后只回读、重复请求、范围变更拒绝、外部改名/完成迁移、缺项/多匹配/标记编辑、不覆盖本地状态/外部重开、冻结保留观察、并发/前置版本改变、权限失败、仅本地派生阻断、在途权限收紧和缺失回读证据拒绝恢复。
- 17 项真实 SIGKILL 检查通过：原有 13 项认知/行动检查；新增 4 项提醒事项尝试/反馈提交前后检查。新增检查使用落盘的外部服务替身，证明恢复只读、无额外外部写、完成最多一个版本，不等同真实 EventKit 保存硬崩溃实测。
- VoiceOS 应用真实系统访问成功，在既有“VoiceOS 验证 2026-10-10”清单创建一项明确标为开发测试的合成任务，唯一标记回读。Apple 提醒事项中改名/完成后，VoiceOS 保留外部标题，行动到版本 2/completed，历史标为 external，原认知仍 unverified。这不是用户真实承诺，不修改个人任务。
- 格式 7 包导出/恢复，十个认知/授权/行动/关联表逐项一致；重开先禁用回读，重新选原清单后实际回读原 ID，未创建新项、未新增完成版本。合成项留在清单中，没有删除。
- 真实旧格式 1–6 分别恢复；schema 7 库复制升级后八个原有表字段全部保留；构建与应用签名验证通过。愿景 23 文件和 AGENTS.md 未变。本轮无新模型调用或原始音视频上传，Apple 自身同步行为不作为“零网络”的承诺。

脱敏证据见[汇总](../research/evidence/reminders-adapter-2026-10-10.json)。真实系统权限撤销、离线/iCloud 延迟和 ID 变化、EventKit 保存硬崩溃、后台监听/睡眠唤醒仍未验证。当前仅按钮触发回读，没有自动轮询、通知监听、原生录制或正式凭据存储。

## 下一步

建立可持久授权的连接范围、变化通知与唤醒回读，再推进字段级三方核对、有限普通可逆外部修改和证据反馈。同步完善用户原始表达身份与自然语言行动提取，避免把现有“外部资料＋显式测试任务”演示当成真实语音自主闭环。
