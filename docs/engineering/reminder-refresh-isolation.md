# 自动发送失败与既有任务回读隔离

日期：2026-10-12。路线 W13–W15，schema31不变。

原自动刷新先发送新任务，再回读全部既有关联；发送抛错会跳过回读，已完成的外部任务可能延迟回流。新增Core编排 `refreshAuthorizedReminders`：先尝试发送，记录阶段失败；取消立即退出，其他发送失败后重新核对持续授权版本，再执行既有关联回读。回读正常也保留发送失败状态，不能宣称全部成功。权限漂移或撤权在回读前阻断；既有一次创建/unknown不重建规则保持。

原生自动刷新改用该编排。测试注入“外部创建已经保存但回执丢失”：第二任务报错时第一任务完成仍回流；第二任务通过标记只读找回，再次刷新不重复创建。完成事实不升级认知的unverified状态。此测试是本地连接器夹具，不能替代真实Apple操作或完整自然案例A。

撤权测试发现原创建返回后在回读之前没有重验授权（只在回读返回后检查）。现已在创建回执标记unknown后、调用find前补充授权版本和取消检查；创建中撤权只保留已发出的尝试，不再执行额外读。

原生失败提示改为“自动同步未全部完成”，避免发送失败而回读已完成时仍误称全部回读失败；任务各自持久状态继续显示。

## 2026-10-13：取消边界

Core 在发送/回读入口与异步预查询返回后检查取消，不依赖原生连接器自行遵守取消。若停止发生在预查询中，即使连接器正常返回，也不能进入创建；若发生在外部保存后，保留 unknown，不追加回读或把迟到完成用于推进本地状态。已发出的保存不能撤回，后续恢复只读核对。尚未进入发送的取消不预留关联。

发送与回读仍保存未知尝试，但向上保留 `CancellationError`，避免刷新编排将取消误认为普通发送故障并继续核对。五个新增回归分别覆盖入口取消、预查询取消、保存后取消、迟到完成回读和连接器主动抛取消；相关 27 项测试通过。它们是本地连接器测试，不代表真实 EventKit 中断或睡眠已验收。
