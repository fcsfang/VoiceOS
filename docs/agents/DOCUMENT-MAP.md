# 文档职责表

本表是文档归属的唯一清单。新增文档前先在这里定职责。一个事实只有一个权威位置，其他文档链接过去。

| 路径 | 职责 | 更新时机 | 不用于 |
|---|---|---|---|
| `AGENTS.md` | 开发规则、授权边界、工作流入口 | 规则变化时 | 任务进展、产品细节 |
| `README.md` | 产品说明、当前基线、构建和验证命令 | 用户可见行为或基线变化时 | 历史设计、任务日志 |
| `docs/README.md` | 稳定文档索引和状态 | 新增或废弃文档时 | 任务进展 |
| `docs/agents/` | agent 工作流和文档职责 | 工作流变化时 | 产品、架构内容 |
| `docs/product/` | 愿景、PRD、决策登记、待确认问题 | 产品行为变化且已对齐时 | 技术实现细节 |
| `docs/VoiceOS：产品愿景与概念设计文档 v1.1/` | 产品愿景基线、PDF 和图表 | 用户确认新愿景时 | 技术实现细节 |
| `docs/licenses/` | 第三方许可证和归属 | 依赖或资源变化时 | 产品、技术决策 |
| `docs/模型api 配置.md` | 本机模型 API 配置说明，已忽略 | 本地配置变化时 | 提交密钥或引用个人配置 |
| `docs/architecture/` | 2026-10-10 的历史设计基线 | 默认不更新；新决策写 ADR | 当前实现说明 |
| `docs/adr/` | 重大技术决策、取舍和退出路径 | 出现跨模块或不可逆技术选择时 | 日常实现备注 |
| `docs/planning/` | 历史计划和路线图 | 默认不更新 | 当前任务状态 |
| `docs/research/` | 一次性验证证据和快照 | 默认不改；新证据新增文件 | 长期结论 |
| `docs/engineering/` | 历史实施记录和开发指南 | 默认不更新；当前构建和验证写 README 与 `.claude/skills/` | 当前实现说明 |
| `docs/testing/` | 历史验收计划、夹具目录和报告模板 | 默认不更新；当前验证方法写 `.claude/skills/` 和 AGENTS.md | 当前验收门槛 |
| `.claude/skills/` | 可执行的验证配方 | 被验证的协议变化时 | 一般说明 |
| `work/TODO.md` | 项目待办和优先级 | 任务新增、开始、完成或调整优先级时 | 任务细节 |
| `work/STATUS.md` | 当前基线、进行中、阻塞和风险 | 会话开始和结束、检查点、阻塞、合并时 | 任务细节 |
| `work/PROGRESS.md` | 已合并改动和里程碑，只追加 | PR 合并、里程碑完成时 | 任务细节 |
| `work/tasks/` | 每个任务的任务卡和检查点 | 检查点、交接、合并时 | 项目级看板 |
| `runtime/` | 本机临时产物 | 从不提交 | 需要共享的信息 |
| `.github/pull_request_template.md` | PR 简报格式 | 交付流程变化时 | 任务详情 |

## 判断规则

1. 长期有效、用户能看到的行为写 `README.md`。
2. 未来代码需要遵守的技术选择写 ADR。
3. 产品定义和验收边界写 `docs/product/`，改动前先对齐。
4. 一次性的证据、探针和快照写 `docs/research/`，不改写旧文件。
5. 项目待办、状态和进展写 `work/` 的三个项目级文件。
6. 单个任务的状态、决策和交接写 `work/tasks/<date>-<slug>/`。
7. 可重复执行的验证步骤写 `.claude/skills/`。
8. 2026-10-10 的设计文档保持历史标注，不按新实现逐段改写。

同一事实出现在两个地方时，以稳定文档为准，修正任务记录或历史文档的索引，不要两边都维护。
