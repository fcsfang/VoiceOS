# H2 第三方应用信息层级实测

## 目标与范围

用户判定 VoiceOS 的信息展示层级「非常糟糕」，本单元对六款信息密集型成熟应用做真实实测，提取可迁移的字号、密度、操作与阅读层级规则。研究只读，不改仓库代码，不写用户资料库。

实测对象：Obsidian、Folo、飞书（Lark）、微信读书、Zotero、Anki。

## 读数口径与方法

三条取数渠道，报告里每个数字都标注来源。

1. `CDP` 指通过 Chromium DevTools 协议读取运行中界面的 computed style，单位是 CSS px。Electron 应用（Obsidian、Folo）和 Anki 的 QtWebEngine 界面都支持这条通道。
2. `像素` 指对 Retina 截图做像素测量。截图设备像素除以本应用的实际 CSS 缩放比，得到渲染点值。所有像素测量用 CoreText 校准过墨高比例：中文字形墨高约为字号的 0.904（17px 及以下 PingFang）或 0.875（20px 及以上）；拉丁大写高约 0.705；拉丁升降部合计约 0.889。校准程序为 `/tmp/textcal.swift` 与 `/tmp/textcal2.swift`，测量脚本为 `/tmp/hier-measure.py` 与 `/tmp/scan-bands.py`。
3. 各应用缩放比不一致。Obsidian 与 Folo 的 `devicePixelRatio` 为 2.629，窗口宽 1240pt 而 CSS 视口只有 943px，说明 Obsidian 运行在 131% UI 缩放下。Obsidian 一栏报告的是反推的基础 CSS 值（CDP 直接读出），截图中的渲染值一律乘以 1.315。Folo 的窗口宽 1512pt 等于 CSS 视口 1512px，无缩放。Zotero、Anki、微信读书、飞书的截图为 2 倍设备像素，点值即像素除以 2。

一次环境中断：测量中途显示器休眠并出现锁屏画面，窗口截图一度全部失败。唤醒后确认会话未锁定（前台应用为「日历」，`CGSSessionScreenIsLocked` 缺失），随后的截图恢复正常。锁屏期间改用 CDP 的 `Page.captureScreenshot` 继续采集 Obsidian 与 Folo。

### 2. 信息密集列表的噪音控制

文件树每行只显示三样东西：折叠箭头、缩进线、文件名。没有类型图标，没有日期，没有大小，没有行内按钮。文件名单行省略号截断。行高 24.9px 加 2px 下边距，即 27px 行距。选中态与悬停态使用同一套浅灰底 `rgba(0,0,0,0.067)`，圆角 8px，文字转 #222。

### 3. 主次操作

主操作就是点击行打开。树行没有任何悬停按钮（CDP 确认行内只有标题子元素，无按钮）。次级操作藏在右键上下文菜单与内容区右上角的「…」菜单里。顶部有返回、前进、面包屑、书图标与「…」组成的操作带，图标按钮 13px 级别。标签页常驻「×」关闭按钮。

### 4. 长内容页的阅读层级

阅读视图上下内边距 32px，正文 16px、行高 24px、段距 16px（`--p-spacing` 1rem）。阅读列实测约 580 CSS px 宽（由窗格 648px 与内边距推算），约 36 个汉字每行。引用块与正文同字号同颜色，左侧 2px 紫色（rgb(152,115,247)）边框加 24px 内缩，不加斜体。链接 #8a5cf5（紫），阅读视图带下划线。强强调 600，斜体仅用 italic。无衬线系统字体。

### 5. 分组与容器

主体是平面白底，没有卡片。分区靠背景明度差与栏位：状态栏 #f6f6f6 加一条 #e4e4e4 顶边框，侧栏与主区之间只有细分隔线。选中行是圆角浅灰块。属性行圆角 6，标签胶囊圆角 28、高 18.2px、字号 14px。层级元素只有一个，就是圆角选中块。

### 6. 密度切换

未发现。无紧凑模式、无行高设置。

### 2. 信息密集列表的噪音控制

列表行结构固定为五层：16px 方形头像（圆角 6）、一行元信息（订阅名 + 圆点 + 日期，10px/700，50% 黑）、标题（17.5px/500，最多两行）、摘要（13px，两行后省略）、可选右侧 64px 缩略图。文本块整体 `line-clamp: 3`。无图行高 112px，有缩略图行高 135px。行内上下 padding 17.5px，左右 20px 和 15px。行与行之间没有分隔线，靠留白分块。侧栏每行 40px 高，文字 17.5px/500，右侧用 5px 小圆点表示未读（绿色）或已读（灰色，opacity 0.6）。

### 3. 主次操作

列表行本身就是主操作，行内没有任何按钮。悬停只把整行染成中性浅灰（约 20% 透明）。次级操作在文章详情页右上角，一排图标：标记已读、收藏、字号、列表视图、阅读模式、分享、更多。空态页面给出四个紫字动作链接，其中最后一个用紫蓝渐变文字作视觉最重项。

### 4. 长内容页的阅读层级

文章页标题 34px/700，行高 51px，是正文（20px）的 1.7 倍。标题块上方留白 60px。作者与日期一行，15px、50% 黑。正文 20px、行高 30px、段距约 1em（由截图推断，computed 未取到段间距）。正文列宽由 `max-w-[clamp(45ch,60vw,65ch)]` 控制，本次窗口下约 754px。文首有浅紫色 AI 总结卡，圆角约 12，标签为渐变文字，正文为骨架占位。正文链接带下划线并用强调色。

### 5. 分组与容器

三栏：256px 侧栏、449px 列表、剩余阅读区。整体平面无边框、无卡片，栏位之间靠背景与留白。唯一有底色的块是悬停行、选中行和 AI 总结卡。错误页是居中布局：品牌图标、20px/600 文案、白底圆角 8 的 Back 按钮。

### 6. 密度切换

未发现紧凑或舒适模式。

## 可迁移规则

每条规则给出数值、证据与适用前提。证据中的数字都能在上一节找到出处。

**R1 双层字号。** 导航与控制层 12 至 15px，内容与阅读层 16 至 20px，两层不混用。证据：Obsidian UI 13、正文 16；Anki 全 UI 15；Folo 元信息 10 至 13、正文 20；Zotero 列表 14。适用前提：应用同时存在浏览面与阅读面。只有一种面（纯列表工具）时可以退化为单尺寸。

**R2 单尺寸分层。** 只有 15px 一档时，用字重 400 对 700 和颜色 #020202 对 #737373 加语义三色建立三层，不靠字号。证据：Anki 的表格、导航、统计行全部 15px。适用前提：用户已熟悉列含义的密集表格，且没有长文本阅读需求。

**R3 阅读标题约等于正文的 1.6 至 1.7 倍，且是唯一 700。** Obsidian 25.9 / 16 = 1.62；Folo 34 / 20 = 1.7。适用前提：长文阅读页。短卡片标题用 500 至 600 即可，Folo 列表行标题就是 17.5/500。

**R4 正文行高 1.5，段距 0.7 至 1.0 倍行高。** Obsidian 正文 16/24，段距 16px；Folo 20/30。适用前提：中文长文。行高低于 1.4 时中文密排难读。

**R5 阅读列宽 36 至 40 个汉字每行。** Obsidian 阅读列约 580px at 16px；Folo 显式 `clamp(45ch,60vw,65ch)`。适用前提：桌面宽屏。窗口更窄时按 ch 收缩，不拉伸。

**R6 单行列表行高 25 至 30pt。** Obsidian 27px，Zotero 28pt，Anki 29.5px，Folo 侧栏 40px。行内 padding 4 至 12px。适用前提：鼠标或触控板操作。触屏目标需要 40pt 以上，这组数字不能照搬。

**R7 表格列数上限 4，且每列独立省略号截断。** Zotero 3 列，Anki 1 名称加 3 数字，Obsidian 树 1 列。适用前提：列宽固定、行不换行。需要更多字段时进详情页，不塞进行。

**R8 元信息与正文同族但不平等。** 元信息 10 至 14px 或 0.7 至 0.9 倍正文，配次级色。Obsidian #5c5c5c，Anki #737373，Folo 50% 黑。注意 Folo 的 `rgba(0,0,0,0.5)` 在白底上对比度约 3.95:1，低于 WCAG AA 的 4.5:1，照搬时要加深或加大字号。

**R9 选中与悬停使用同一套中性色底，圆角 8 至 12，不用彩色高亮。** Obsidian `rgba(0,0,0,0.067)` 圆角 8；Anki #e4e4e4 圆角 12；Zotero #303030 行首尾圆角；Folo 中性 20% 悬停。适用前提：选中态需要与状态色共存。彩色保留给未读、计数、错误。

**R10 语义色来自一套标准调色板，只用于数字与状态。** Anki 用 #3b82f6（新）、#dc2626（学习中）、#16a34a（待复习）、#737373（次级），正好是 Tailwind 的 blue-500、red-600、green-600、neutral-500。微信读书只用蓝（主操作）与橙（当前分类）。适用前提：全应用只有一套状态色，色值从调色板取，不手写。

**R11 一屏一个实心主按钮。** 主按钮高 25 至 36pt，文字 13 至 16px、500 至 600，圆角 15（胶囊）或 8 至 12。Anki 开始学习 #306bec、高 25、圆角 15；微信读书阅读按钮高约 36；Zotero 横幅完成按钮蓝底白字。其余动作是白底胶囊、描边或文字链。适用前提：每个屏幕有一个明确的主任务。没有主任务时不要硬造按钮，Obsidian 和 Folo 的浏览面就没有主按钮。

**R12 行级操作隐藏到悬停、右键或详情页头部。** Anki 悬停出齿轮；Zotero 与 Obsidian 用右键菜单；Folo 用详情页右上图标行。适用前提：桌面指针环境，主操作是打开行本身。触屏环境需要常驻「更多」入口替代。

**R13 容器最多两层。** 画布层加一层模块卡。Anki 只有一张白 40% 卡（圆角 12、1px #e4e4e4、padding 15、极浅阴影）；Obsidian 与 Folo 干脆全平面；微信读书是深底加圆角卡。适用前提：内容本身已经密集。每多一层底色，扫描成本就增加一层。

**R14 字重四档封顶。** 400 正文、500 按钮与行标题、600 行内强调、700 标题与表头。证据：Obsidian strong 600、标题 700；Anki 全 700 表头；Folo 行标题 500、动作 600。适用前提：任意界面。超过四档后字重不再可辨。

**R15 深色模式用两层底色。** 画布 #1e1e1e 加选中 #303030（Zotero），或 #000 加 #191919 卡（微信读书）。不做大面积阴影，不引入第三种灰。适用前提：深色主题。浅色模式对应的是 #fff 或 #f5f5f5 画布加 #f6f6f6 条带（Obsidian 状态栏）。

## 对 VoiceOS 的直接含义

以下为按上述证据做的推断，标注为推断。

- 控制中心的列表与卡片行按 R6、R9 做：行高 27 至 30pt，选中用中性灰底圆角 8，不用彩色高亮。
- 阅读页按 R3、R4、R5 做：正文 16px 至 20px、行高 1.5、标题约为正文 1.6 倍、列宽不超过 40 汉字。
- 若保留「行动」「材料」这类多字段行，按 R7 把列压到 4 以内，元信息用 11 至 13px 次级色，行内不放按钮（R12）。
- 一屏只留一个实心主按钮（R11）。VoiceOS 当前多处强调色同时出现的问题，可直接对照 R9 与 R10 收敛。
- 现有层级若依赖多种字号，可参考 Anki 的单尺寸方案削减一档（推断，需要 H3 现状数据验证可行性）。

## 取不到的项目与原因

- 飞书：扫码登录需要用户手机。调试端口被应用忽略，资源目录里的界面动态包不可读。只测到登录页。
- 微信读书：阅读器显示「付费会员可读」，无法进入正文页。列表与书籍详情页已测。
- Zotero：条目详情面板、笔记与 PDF 阅读未打开，本次视图右侧为空态。列表、侧栏、横幅已测。
- Folo：部分缓存条目的详情返回「The entry you're looking for could not be found」，属应用数据状态，不是测量失败。成功捕获一篇完整文章排版（JSTOR Daily）。
- Obsidian：未发现任何行内悬停按钮，这本身是结论；设置弹窗未测。
- 中途显示器休眠并出现锁屏画面约十分钟，窗口截图临时失败，后恢复。期间改用 CDP 截图继续观测 Electron 应用。所有应用在测量结束后已恢复原状态（Obsidian 与 Folo 以正常方式重新启动，其余由本次启动的应用已退出）。
