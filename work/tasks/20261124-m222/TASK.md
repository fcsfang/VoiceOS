# 222 启动对账：过期摘要条目退役

现象：13:47 的语音备忘录已经处理成功（receipts 里有当前内容摘要），入口里却还挂着一条旧摘要的 needsAttention 条目。原因是文件时间戳没变，扫描在 `baseline == stamp` 处直接跳过，221 在 receipts 分支加的清理永远不会触发。

## 改动

- `start()` 增加一次异步对账：对非处理中、有 fileStamp、文件仍存在的条目按当前内容重新计算摘要；若该摘要已在 receipts 且与条目 id 不同，条目退役（同步清 failures）。
- 哈希在后台线程执行，只对少量待处理条目各算一次，不影响启动响应。
