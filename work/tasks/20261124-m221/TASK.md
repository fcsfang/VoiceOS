# 221 复审收口：入口状态机、配置权威与 Python 修复轮

三份只读复审（入口状态机、启动配置链、Python 核对链）的发现收口。

## 入口状态机
- `resumeDeferred` 只唤醒 `attempts == 0` 的暂缓条目：真实瞬时失败（429/5xx）至少重试过一次，保存配置时不再被提前唤醒烧掉预算。
- 文件消失判定加 `fileExists` 复核并落盘：写入中、0 字节过滤、同步临时名不会整轮缺席就误判「已移走」。
- 摘要只复用「已在 receipts 里」的条目 id，其余按当前内容重新计算——修掉旧版本摘要被沿用到新内容、点重试会以新摘要重复导入的问题。
- 同一文件版本已处理（receipts）或新版本开始处理时，退役同路径上旧摘要的非处理中条目；文件改名移动时更新条目的 path/fileStamp 而不是误报「另一个入口」。
- 移除入口时同步清掉它的失败标记；消失判定有变更时 `save()`。
- `canProcess` 与 receive 的 blocker 对齐（模型环境、表达模型、整理脚本）；`deferred` 等待改用第一个重试间隔。

## 配置链
- 内部配置「存在但解码失败」与「不存在」区分开：损坏时明确提示重新保存，不再静默回退去覆盖。
- 新增 `modelConfigIssue`：配置存在但不可用的具体原因（钥匙串、地址策略、损坏）显示在设置模型卡、健康卡、处理情况页与引导页，不再被「尚未配置」盖住。
- `installTextModelSuite` 接收并保存安装时的地址/密钥/型号/强度快照；`textModelOrganizerEnvironment` 直接用快照，端口与整理脚本不会再读到两份配置。
- 文件导入的钥匙串写入失败改为显式失败；保存内部配置时密钥没变不再重写钥匙串（只改型号/强度不会因钥匙串锁定失败）。
- 历史配置路径导入失败时移除该键，避免每次启动重复同一错误。
- `TextModelConfiguration.validated()` 与 `LocalTextModel` 的地址解析去掉尾部 `/`，与端口策略的精确 `/v1` 一致。
- `BilingualClient` 补 `TextModelHostPolicy` 校验与密钥检查，预览不再声称已配置。

## Python
- `settings()`：地址与密钥不得跨源配对到不同主机；损坏文件（非 UTF-8、结构异常）按「文件不可用」处理。
- `_merge_repair`：修复轮只能处理首轮出现过的片段；重复 span_id 保留第一条；首轮有效校正必须原样保留。
- render-only 不再回退到不带身份校验的 v5/基目录缓存，缺缓存时报出期望目录；只读渲染缺配置时错误里带缓存路径。
- 已知取舍：缓存身份加入端点/模型/强度后，217 之前的旧回执与旧缓存目录不再命中，未完成的整理会按新身份重新请求一次。
