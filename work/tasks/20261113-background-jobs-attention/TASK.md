# 后台任务注意力降级：失败不再当待办

## 目标

用户反馈「思想与目标跟进未完成」「知识核查未完成」这类后台增强任务的失败长期占据待办位置，不知道怎么处理，也感觉没有价值。产品决定把它们从全局注意力里降级，并给一个批量重试入口。

## 数据依据（2026-11-13 对实时库只读查询）

- 36 段录音有跟进回执，25 段最新一次完成，11 段失败。
- 知识核查 43 次，15 完成、18 失败、10 冻结；完成的 15 次里只有 3 次发现过问题，采纳数据为零。
- 冻结观点 323 条、行动 229 条，真正影响理解的是第三套积压「AI 提取已暂停」，不在这次范围。

## 决定

- 全局橙色横幅 `workspaceNeedsAttention` 不再计入跟进失败与知识核查失败；两类区块仍保留在「处理情况」页，可逐条重试。
- `resumeKnowledgeReviews` 删除全库扫描排入循环，新核查只从录音整理后自动排入或手动重试进入队列；队列 drain 不变。知识核查的快速路径判断仍服务于排入时的去重。
- 「处理情况」页两个失败区块各加「全部重试（N）」，实现就是按现有单条路径往队列排入，drain 复用现有循环，不新增状态机。知识核查区块从每条一个同名区块合并为一个带计数的区块，与跟进区块一致。

## 范围

- `Sources/VoiceOSApp/WorkspaceProcessingView.swift`：注意力汇总条件、两个失败区块与批量按钮。
- `Sources/VoiceOSApp/VoiceOSApp.swift`：`retryAllFailedFollowups`、`retryAllFailedKnowledgeReviews`、`resumeKnowledgeReviews` 扫描移除。

## 非目标

- 不引入「忽略/已读」状态，不加迁移。
- 不动单条重试与队列语义，不动冻结行动的批量重新识别。
- 横幅仍可能因暂停待办、转写核对等真实事项亮起，这是预期的。

## 验证

- `swift build -j 4` 通过；`swift test -j 4` 95 项 0 失败。
- 实机核对未完成：处理面板的内容在辅助功能里只暴露为不透明容器，窗口截屏与应用内面板开合不同步，隔离副本里按不到面板内容。横幅状态在该资料库上也会因暂停待办继续亮起，截图无法区分。改动为显式条件删除与区块重排，逻辑经代码审查。
- 手动核对路径：首页底部「查看处理」→ 跟进与知识核查区块各有「全部重试（N）」；横幅只由其他真实事项点亮。
