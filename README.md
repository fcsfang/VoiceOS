# VoiceOS

让自然表达被忠实理解、长期记住、恰当唤起，并与现实行动形成持续循环。
产品定义见[愿景 v1.1](docs/VoiceOS：产品愿景与概念设计文档%20v1.1/VoiceOS_产品愿景与概念设计文档_v1.1.md)，开发方式见 [AGENTS.md](AGENTS.md)。

当前以本地 `main` 推进功能，优先跑顺一次技术访谈的完整闭环：
录音 → 转写 → 理解 → 观点和任务 → Apple 提醒事项 → 结果回流。

## 构建和运行

```bash
python3 scripts/app/build.py --semantic-model runtime/bge-coreml-2026-10-11
python3 scripts/app/run.py
```

构建使用本机已有开发签名与本地模型资源，不下载模型。
日常应用默认使用优化后的 Release 构建；需要调试时可给构建命令加 `--configuration debug`。工作区列表按可见区域创建内容，日期解析和显示使用可复用的格式策略；完整整理只在数据阶段完成时刷新资料，日志进度在后台读取，不再每两秒重读并发布整个工作区。
数据默认保存在 `~/Library/Application Support/VoiceOS`；文本模型使用项目本地 `.env`。
默认不为同一结论重复生成初稿和复核稿：标题与摘要一次，提醒字段一次；思想跟进按“选择相关历史 → 基于完整相关依据生成”完成。全文任务漏项检查、真实引用、版本与许可校验、提醒写后回读保留。跟进完成后只存实际引用的历史依据；普通材料查询不读取跟进历史大字段。清单不自动生成重复 CSV，逐字稿可读副本只在整理完成后输出一次。
本地转写统一使用应用保存的 Qwen 配置。
Qwen 优先按实际停顿分段，保留全音轨和真实时间范围。每段完成后把进度持久保存在资料库的 `转写进度/`；失败、停止或重开后，同一音轨与配置从断点继续。重用前核对完整音频内容指纹。单段输出异常时自动拆短重新识别，仍失败则保留此前进度并显示原因，不保存残缺段落。全文校正由 AI 直接阅读完整逐字稿并修正识别错误，明确修正自动采用，真正无法确定的内容保留疑义；不再默认定位疑点、重复本地识别或强制多轮裁决。AI 校正成功即替换初稿，只保留当前校正稿、音频时间、修正数量和仍有疑义的内容；知识判断另行核查。ffmpeg 导出副本在原音轨入库成功后删除；成功的模型调用只保留可续作的结果和简要终态，流式事件、部分正文与完整响应副本随即删除。失败中间结果只用于恢复尚未完成的阶段。
原件完整性在每次启动时重新核对；同一次运行内，文件身份、大小、修改时间及文件系统变更时间均未改变时复用已完成的哈希核对，避免读取每项观点和任务都重扫完整音频。原话版本及授权仍按当前数据库检查，文件变化会重新核对并暂停失效内容。界面按批次读取各录音的最新观点，并共享后台跟进的有效性核对，避免每份录音重复扫描全库。
工作区在一次资料库读取中取得相关状态，合并同时到来的刷新；问题历史、录音回执和主题关联批量读取。单份材料与单条观点只核对其实际依据，损坏原件仍会暂停相关理解与行动。长文本流式请求保存请求标识、增量、服务端终态与用量；完成、未完成和失败分别处理，收到终态立即结束，不等待网关关闭连接。网络超时按无数据活动计算，不以总耗时十分钟切断仍在工作的模型。High 推理为推理与正文保留充分的输出预算；明确预算不足时自动提高预算重试。

需要独立试用库时：

```bash
python3 scripts/app/run.py --data-dir runtime/dev
```

## 统一工作区

默认使用「石墨」中性灰阶主题；“设置 → 外观”可切换原有的「鼠尾草」绿调，并选择跟随系统、浅色或深色。选择即时生效、重开保留。

主导航为「首页 / 主题 / 材料 / 行动」。材料入口按最近加入时间列出全部录音、视频和文字，显示内容标题、日期与原文件名；选择材料后直接查看该份理解、相关行动和完整原文。主题入口继续按问题与内容组织跨材料阅读。首页呈现真实资料生成的 AI 简报、重点材料与交付，切换「全部动态」可找回完整资料及处理情况。主题按问题持续组织跨周、跨月的材料，在「概览 / 认识与问题 / 行动与结果 / 材料」之间切换。概览保留主题速览、内容目录与最近关联；完整小主题卡片集中在“认识与问题”，可展开对应原话、观点和行动。已有前后观点关联保留双方原话和出处，实际反馈可返回对应行动。观点与任务按具体语义分配到小主题，不因同属一段录音而全部带入；引用必须能在完整原文逐字定位。已完成行动与实际结果分别展示，AI 交付单独标明。材料图谱与日、周、月回顾收在“认识与问题”的阅读方式中。材料、任务和 AI 报告在中央工作区打开，右侧讨论默认收起，展开时保留阅读位置。原话、核查与修订历史按需展开；模型、自动入口、提醒事项和资料迁移统一放在「设置」。
材料页提供「日常材料 / 已归档 / 回收站」，列表与详情均可管理。归档只从日常列表收起，仍可作为历史依据；移入回收站需确认，撤回文字云端许可并暂停相关理解，原件、原话和任务状态历史保留，不永久删除文件。连续表达的各段一起归档或移入回收站，节目原文仍单独保留。回收站可逐份恢复，先核对原件，恢复后仅本机保存，旧理解不会自动启用；缺少原件的迁移包恢复为仅有文字的材料。schema47迁移包保留归档、回收站状态及所选原件。Apple 提醒事项未被删除或取消，仍可能通知。材料详情直接显示「更正原文」，观点旁直接提供「更正理解或归属」「停止使用」，主题阅读卡片也可直接纠正已有观点，原始输出与修订历史保留。
底部“查看处理”始终可打开当前转写、AI 全文校正、理解、跟进及模型与提醒事项状态；失败保留具体原因与材料入口，结果未知的请求不会自动重发。行动分类为空时明确说明，暂停的待办显示实际登记的完成状态；材料页说明具体原因并提供“重新识别观点和任务”、完整文字及转写更正入口。仅更新转写核对记录时明确说明文字未变，重新识别复用同次处理回执；已完成任务和已被新识别替代的提取记录放入历史，不反复计入待处理。更正观点后，可在关联任务中查看更正内容并填写准确的新待办。Apple 提醒事项的实际通知状态单独保留。启动只推进已保存的处理请求，不因历史录音曾获文字授权而自动校正整个旧资料库；显式整理和已排队录音在理解前仍执行完整转写核对。后台处理按每份材料和阶段发布结果，不定时重读整个工作区。自动入口的目录枚举、稳定性复核和内容哈希在后台读取，避免周期扫描阻塞点击和滚动。资料库打开失败时直接显示原因，可重试打开或选择其他库；不会自动清空或重建资料。
文字录入的保存操作固定在页面底部；切页、稍后继续或退出重开均保留标题、正文、归属与许可选择，保存成功才清空草稿。草稿在当前资料库的 `草稿/` 目录自动保存，恢复草稿不会自动发送或理解；正式入库仍需点击保存。草稿不随资料迁移包导出。其他内容正在理解时明确提示，可先仅本地保存；保存结果返回本次材料，不会误开后来选中的其他材料。
全局搜索支持 ⌘F 并自动聚焦输入，忽略查询首尾空白，按行动、理解和材料分组，可一键清空。任务结果草稿在本窗口内按任务版本保留，切页核对原文后可继续填写；关闭窗口前仍需正式保存。文字录入支持选择或直接拖入一份 UTF-8 txt/md 本地文件，在后台读取全文，替换已有草稿前确认，取消后保留原输入；导入默认外部资料、仅本机，标题超过 100 字时在保存前提示，完整正文不截断。页面明确区分仅本地保存与发送云端理解。

首页与主题、行动分类使用醒目的大字号切换入口，窄布局自动换行；交付、材料、主题及下一步分板块呈现。长简报、主题脉络与要点可展开阅读全文，材料要点按序号分隔，报告区分标题、正文与代码，完整原话和修订记录仍可追溯。

获文字云端授权、完成转写校正的材料会自动归组并更新主题理解和首页简报，保留完整原文与真实归属。AI 主题名是元数据，不会伪造为个人表达；AI 报告会接回主题。原话、任务或授权变化后，过期简报暂停展示并自动更新，失败可重试。历史的仅本地材料继续沿用原许可。新个人文字默认允许 AI 理解，也可选择仅本地保存；讨论输入后直接发送，明确委托由助理自动执行。

## 连续录音自动合并

自动收件箱与语音备忘录入口先完整转写同批稳定文件，再由主模型阅读完整文字、录制时间和跨段衔接，并独立复核是否属于同一次表达。连续录音自动按顺序整体理解，不需要多选、分组或点击合并；仅话题相似或时间相近不会作为充分的合并依据。时间未知时不假装有精确顺序，含糊的连续性先独立保留，后续补录可提供新的接续依据。

稍后同步到的新分段会与已接收的完整表达自动对照（入口只记录来源，不阻断跨入口接续），确认接续后，结合全部分段重新整理观点、条件、否定、自我修正和任务。逐段原音、原话与回听时间保留；材料列表将连续表达作为一个入口，展开可查看所有分段，讨论也带上整次表达。合并关系存入资料库，失败或重开后沿用已保存的转写与分组，不依赖开发助手参与。启动后会为升级前已自动导入、已完成转写且仍允许文字处理的录音补充连续性判断；旧的收件箱完成回执不再跳过这一步，未导入的历史文件仍留在原处。确定独立且已有有效完整理解的单段复用原结果，新增合并关系才重新整体理解。

补录后的行动经独立核对沿用原任务身份、真实完成与反馈；接续链记录原提取、新提取和独立核对回执，随资料迁移保留。明确撤回的未完成意图退出当前待办，撤回不记作已完成。新任务在整体验证通过前不发送提醒。已经连接的正式 VoiceOS 提醒仅在唯一身份、原标题及相关字段未被外部改动时自动接续；撤回时保留原提醒记录并清除日期和通知，不删除历史、不伪造完成。外部编辑或身份冲突保留原项并显示原因。自动入口按资料库隔离配置，独立试用库不会接收日常库的录音。

## 思想与下一步

主题材料详情汇集当前有效的观点、问题与收获；全局搜索可查找正文、录音标题、理解与行动。选择内容后可展开原话、回听、讨论这条思考，查看已保存的前后思想关联与同段任务及其结果。讨论以所选观点为中心，带上有效的旧观点关联、同段任务状态和实际结果原话；AI 整理摘要与用户原话分别标明。长录音按完整内容准备上下文，不再受普通短讨论的固定预算限制；当前仍向模型提供完整相关录音。自动纠错不会显示为用户改变了观点；未核实的模型关系仍是依据个人表达形成的理解。
材料详情的普通讨论、主题回顾与讨论成果统一按完整原文和实际已有回复准备输入，不再受 4000 字入口、40 轮讨论或固定回复段数的限制；超出请求或模型容量时明确失败，不裁剪证据。返回材料时同步选中状态，讨论历史按当前材料读取；异步打开讨论后若已切页，不会把旧讨论挂到新页面。讨论侧栏始终标明材料或主题，并与当前草稿所属会话一致；在本次窗口内切换讨论会保留各段尚未发送的草稿，追加讨论提示也不会覆盖已有文字。
知识库内可以直接认可整理、更正表述或归属、停止使用并查看审阅历史。认可不等于事实验证，也不会暂停已有任务；更正或停止使用仍会冻结相关行动，历史保留。
录音详情和知识详情的“知识理解核查”另行检查完整个人原话中的知识判断：先找全文候选，再仅用公共概念进行 web_search 查证并独立复核，不把个人原话或私有背景作为检索词。结果展示对应原话、问题解释、更准确理解建议、适用边界、反例及实际来源。核查不会改写原话、冒充用户接受修正或自动修改任务；没有建议只表示本次未提出纠偏，不表示全文正确。失败可重试，原话、理解或授权变化后旧核查冻结为历史；知识卡只显示可按连续原话定位的建议。
“认知地图”默认按主题与问题探索跨时间的完整脉络；日、周、月放在“周期回顾”，用来查看新增活动及其历史背景。主题可以是关注领域或具体问题，复用已有长期探索资料，不要求表达前先分类。支持日期跳转、前后周期、缩放与内容定位；可切回时间线查看。点击节点或关系可查看完整原话、归属、任务版本与前后思想依据。实线来自已有来源和任务关联，虚线标明 AI 思想关系提案；跨主题的新增联系仍由 AI 回顾提出。旧资料作为背景标注，完成登记依据实际状态记录时间，任务卡片显示当前状态；两者都不等于已经学会或获得成果。录制时间未知时按导入时间排列并标明。
“一起回顾”把所选周期及相关旧资料的完整原文、有效观点、任务状态、实际反馈和思想关联带入讨论，预填可编辑的回顾问题；输入后点击发送，应用先保存原话再请求模型。AI 可比较学习主题、联系与区别、认识变化和未解问题，再提出更高层次的理解与下一步。回顾讨论可重开、继续讨论和保留成果；更正原话或观点、任务与结果更新后，旧回顾暂停使用，需从当前周期重新进入。基于进入时选定的资料，不自动纳入之后的新记录；超出模型上下文时明确失败，不静默截断原文。知识库只为确有对应原话的观点展示后续关联，不把同一录音的其他观点混在一起。
地图中的“主题与问题”可创建持续探索的问题，关联完整资料，记录自己的认识、认识变化、小验证与实际结果，并为结果附上对应尝试的原文。问题标题与记录均保存为个人表达，默认仅本机；云端回顾沿用每份实际原文的许可。记录可撤回，原文历史保留；资料修订或记录撤回后，旧依据标为不可用，旧回顾及派生知识暂停使用。问题及记录随资料包导出恢复。
日回顾找回思考现场，周回顾连接材料、冲突与未解问题，月回顾对照真实的前后表达。AI 提出的跨主题联系需说明双侧依据、共同机制、差异与边界；小验证建议包含判断、尝试、观察与修正条件，保持待核对。讨论中的“核对联系”“找反例”“设计小验证”仅添加可编辑草稿，保存后再发送。地图支持只看所选节点的相连关系、搜索跳转和重置；“认识对照”并排展示已有 AI 关联的前后原话及来源，支持继续讨论，不自动认定用户成长。
任务和目标展开后可选择“继续思考”，围绕该事项带入完整来源、所属目标和实际反馈；旧版本结果明确标为历史。打开窗口不会自动发送 API 请求。所选任务或结果变化后，需要从当前事项重新进入讨论，避免继续使用过期上下文。

主题材料和全部动态按内容显示录音标题与日期；详情有简短摘要，原文件名收在“原文件信息”。新录音转写后自动调用外部 API 阅读完整逐字稿、生成标题和摘要；已有录音复用保存的转写补齐，不重跑音频或任务提取。仅处理获文字云端授权的录音。材料详情的“修改标题”可自行改名，手动标题不会被自动整理覆盖；更正逐字稿后，自动标题按新版本重新生成。

内容标题仅在 VoiceOS 内使用，不回写语音备忘录或 iCloud；语音备忘录的自动导入照常可用。

“行动”集中显示已有待办、AI 代办和真实结果；思想跟进、自动入口与维护位于设置。没有说出的日期不会补上；建议选用后才成为待办。完成任务可以补一句实际结果或收获，也可以跳过；重新打开并再次完成任务后，可记录这次的新结果，旧反馈继续保留。
任务完成、重新打开或选择目标步骤后，自动更新所属目标的下一步，不再误选最近的无关录音。结果反馈按关联任务接回目标；步骤状态或实际反馈变化后，旧目标建议暂停使用，其他思想和练习反馈继续保留。知识库的“行动结果”可搜索任务、结果原文和录音标题，旧任务版本的收获明确标为历史记录。工作台集中显示后台处理进度、待更新目标及失败原因，可直接重试。
允许自动处理的任务反馈会先整理为可检索的个人思考，再接续思想与目标跟进；原任务、反馈原话和新观点可互相打开。仅本地保存的反馈不自动发送，重开应用会继续已授权的整理，完成状态和证据状态分别保留。

录音完整整理后，应用自动调用外部 API 生成三类跟进，可从“设置 → 其他工作与维护 → 思想关联、目标下一步与英语反馈”查看：

- 对照历史观点，保存支持、限定、不同判断或延续关系，以及前后原话和来源。当前理解与历史同时保留，模型关系判断不等于事实验证。
- 为本次表达相关的明确长期目标生成阶段行动和当前下一步；结合新口播、进展及提醒事项完成状态调整。建议不会直接变成承诺，选用步骤后才创建任务并同步正式清单，已有任务会沿用。
- 实际英语练习自动寻找旧练习及其反馈，提供表达建议、重复问题和有依据的变化比较，以及下一次短练习建议。不提供基于文字的发音评分。

原话或授权更改后，旧结果保留为历史并暂停使用。可选择已有录音补齐或重试跟进；重开应用会继续显示保存的结果。无需开发助手参与正常运行。
完整整理在观点和任务保存后即完成入口处理，提醒日期及优先级核对、思想关联与目标建议在后台继续，不阻塞下一段录音或自动导入；未核对的新任务等待字段完成后再发送，既有提醒的完成状态仍独立回读。重开应用继续未完成的后台跟进；临时断网、超时、429 或服务端故障保存原因并在 60 秒、300 秒各自动重试一次，唤醒及定时检查继续到期任务。授权、原话变化或内容校验失败不自动重试，可在“思想与下一步”查看原因并重试。思想关联、目标建议与英语反馈分别核对有效性，某个阶段任务完成不会隐藏其他仍有效的结果。后台请求只校验其真正使用的原话、观点和任务，其他新录音不会让有效结果被无故丢弃。模型先阅读完整当前录音与全部历史目录，选择相关历史，再对相关条目的完整证据直接生成跟进；不设条目数量上限，不为每段录音重写无关目标。

## AI 助理代办

“记录想法”支持完整txt/md、粘贴原文和明确归属；长文字不会因保存长度被拒绝。外部文章理解保留作者归属，作者的行动不能变成个人任务。

任务页的“交给 AI”可以委托调研、比较或文本起草：编辑交付要求、查看完整任务原文、允许本次云端处理，并选择成果要接回的主题。应用保存委托后自动执行，可从任务页和“现在该推进什么”查看排队、执行、失败及成果。重开应用继续排队工作；执行中退出的请求保留为失败，手动重试，避免重复交付。

已有内容处理许可范围内，应用对当前个人待办按原话识别明确的 AI 委托并自动代办；“我以后想研究”这类计划不自动执行。需要关键资料或不支持的操作会说明原因。首版只执行调研、资料比较和文本起草，不发送消息、购买或修改外部系统。互联网调研使用 Responses 的 web_search；模型服务不支持检索或没有真实工具引用时明确失败，不把模型记忆当作调研。

完整报告、实际引用和响应身份保存到本地，可取消、重试、关联主题或带着成果继续讨论。报告可另存为Markdown并直接记录使用结果。工作台的识别失败支持手动重试，不自动将未确认的意图当成委托。AI 报告归属为 AI 材料，不自动改成个人观点，也不自动把原任务标为完成。原话、更正、任务版本或许可变化后，旧交付保留为历史并停止用于后续理解。

## 缺陷补齐与愿景差距

本轮优先推进两项 P0：云端理解前自动校正完整转写，以及独立的知识理解核查。三项受影响的核心集成流程通过；独立资料库的原生界面已用公开合成录音完成本机 Qwen → 真实模型全文校正（历史双重校正流程已改为直接 AI 校正） → 理解 → 实际联网查证。示例中的 SQLite 外键判断保留在原话中，知识核查引用官方文档指出问题，并排除个人偏好；网络中断后的界面重试也已完成。另一个 Qwen 合成语音对比例只证明停顿处断句改善，不能替代真实口述准确率验收。真实提醒事项和跨设备体验须分别验收。

## Jev 提速评估

2026-10-15 使用本地配置实测 Jev 1.13（实际返回 `typesafe/jev-1.13-20260917`），对照当前 `gpt-6.1-sol`。扩大至 208 个合成案例，包括 4 份完整访谈上下文；1 条“同事明天交稿”是否能推出“用户明天检查”的标注歧义单列，207 条参与评分。开发集 88 条，未参与调参的验证集 119 条；同场景的正反提案不跨集合。共取得 1,552 个 Jev 原始问题回答，另做 7 轮同批任务的顺序、实际回退与相同输出对照实验；这些回答与复测不是独立样本。

| 调用方式（同样应用来源等确定性约束） | 207 条明确案例中的错误 |
|---|---|
| 原有较长的单次提问 | 1 |
| 简短中文直问 | 0 |
| 通用原子问题拆分后组合 | 5 |
| 中文判断与另一种表述一致、高概率才接纳，其余回主模型 | 0 |

来源身份、同源排除、引用定位、授权及已有任务状态交给代码；模型只判断窄范围语义。实验中的保守规则在验证集运行前固定：两种表述指向同一结果、选项概率均至少 0.98 才接纳；证据否决一律回主模型，不能自动删除任务或依据。置信度和多次一致都不是正确性保证；未见场景仍需验证。本组中通用原子拆分反而增加错误，不能把更多问题当作更可靠。

相同输出格式的最终对照，双方先应用同样代码约束，只返回任务分类，不生成解释；混合方案计入 Jev 和主模型回退的全部等待。24 条合成任务按三种顺序实测如下，双方均无最终错误：

| 输入顺序 | 纯主模型 | Jev + 回退 |
|---|---:|---:|
| 原顺序 | 10.19 秒 | 14.11 秒 |
| 逆序 | 115.70 秒 | 21.26 秒 |
| 轮转顺序 | 10.34 秒 | 9.08 秒 |

纯主模型中位数 10.34 秒，混合方案 14.11 秒。混合方案在一次长尾等待中明显更快，但没有证明稳定提速。此前“主模型生成解释、Jev 自动通过项只返回分类”的计时不是等量工作，不用于接入决策。这些都不是完整录音闭环的性能测量。

优化调用方式目前只在独立实验中运行，不切换正式资料处理，不取消主模型最终核对。观察到零错误不等于错误概率为零；当前也未满足稳定更快的条件。可保留窄中文问题、代码先核对确定性约束与不确定时回退的方式，暂不让 Jev 独自丢证据、合并任务或放行提醒写入。本机输入、回执、固定规则、歧义标注说明及计时保存在 `runtime/jev-expanded-20261015`，汇总为 [decision.json](runtime/jev-expanded-20261015/decision.json)，不包含凭据；首轮实验仍保留在 `runtime/jev-evaluation-20261015`。

## 实际播客的完整任务整理

在“记录想法”点击“导入音频 / 视频”，选择完整音频或 OBS 视频、确认本人音轨，再点击“完整转写并整理”。
固定录制格式使用从 0 开始的音频编号：音轨 0 是混音、音轨 1 是本人麦克风、音轨 2 是系统内录。三音轨视频默认沿用已确认的归属，无需每次说明；本人轨与节目轨分别完整保存、转写和核对，保存同次录制与实际时间偏移。理解、讨论和后续核查带入获许可的双方全文，具体语义关联保存双方原话；转述不等于赞同，节目观点与节目安排不会变成个人立场或任务。节目原文或许可变化时暂停旧关联，按当前依据重新整理。界面显示实际完整时长，不截取试验片段。Qwen 转写、逐段提取、全文漏项复查和清单保存连续完成，进度可见，也可以停止。
已完成 Qwen 转写的个人录音可以直接“完整整理全部意图”；已整理素材显示“已完整整理”，避免重复调用模型。
“导入已完成的全文整理”和命令行导入同样要求完整 API 核对回执；所有录音预检通过后才接入。
也可以选择“开始我的口述 → 录制并完整整理”，停止后自动完成同一流程。新录音中的观点与收获独立保存为知识，只有明确待办同步提醒事项。
原件和逐字稿保留在资料库，完整清单保存在资料库的 `整理/` 目录。
意图提取、漏项复查、合并及最终核对修订均调用已配置的外部 API。正式文本流程统一使用 Responses。2026-10-14 的 Chat Completions 对比保留为实验结果：该中转路径在长稿初稿覆盖上更好，但底层路由差异和整条生产流程的收益尚未确认，因此撤回正式切换。已完成结果继续复用。最终核对区分行动意图和待研究事实，自动修正过度保守的待核对标记，并检查引用、条件与否定关系；真正含糊的内容保留回听入口。自动流程不读取人工修订文件，API 核对未完成时不会把初稿同步到提醒事项。
默认续作复用已有转写与模型结果；`--render-only` 只重生成已完成 API 核对的清单，不发起新请求。
新录音整理时，外部 API 同时核对已获文字处理授权的原任务：明确重复提及接回原任务，真实进展与收获保存为带原始录音入口的接续记录，不重复创建提醒。不同交付物或关联不清的内容单独保留；进展不自动改变任务完成状态。原任务或授权在处理期间变化时，保留清单并提示重试核对。
这些步骤由应用自动组织输入、发送项目中保存的提示词、校验结果并落库，不读取开发聊天或依赖人工改清单。产品运行以内容效果和正确性优先，必要的多次 API 调用不以节省费用为目标。
任务合并后做一次全文意图核对；已有任务接续由 AI 直接判断，再校验任务身份与原话。转写校正改为一轮 AI 全文直接校正，输入逐段包含原文和标识，覆盖整条音轨；程序只检查引用定位、修正范围和版本，自动采用明确修正，不要求用户逐项审稿。原始录音保留，AI 校正成功后只保留当前稿，观点、任务、摘要和后续跟进共享当前稿。确实无法确定的词句保留疑义，同段其他明确意图照常使用。知识错误另走知识理解核查。

使用完整本人音轨的 Qwen 逐字稿，按时间提取并独立复查漏项，再合并重复事项。
每个完整窗口提取一次，再通读全文补齐跨段遗漏；合并后进行一次意图与引用修正，不默认重复逐窗提取、三份清单比较或多轮裁决。已完成资料不会自动全量重跑；失败续作复用已有转写和有效模型回执。
保留具体待办、需要记住的问题、长期目标、产品需求和待核对意图，每项附原话与时间，不限制任务数量。

任务清单与完整逐字稿可导入日常应用；导入保留未完成状态，歧义和长期意图留在机会池。
录音中已处理的即时操作保留在清单中，不重复创建提醒事项。首次在应用中选择“新建并连接 VoiceOS 清单”，
再给导入命令加 `--allow-reminders`，明确仍需跟进的普通任务会由应用自动同步并回读。

“行动”集中显示待跟进、待核对、问题与目标、已完成及录音活动。
完成状态与已连接的 Apple 提醒事项双向同步；可以随时补充实际进展、结果或收获。
结果窗口支持“口述进展或结果”：停止后由 Qwen 本地转写，核对文字再保存；反馈保留原始口述入口。
Apple 提醒事项只显示核心待办，不自动添加备注链接；原话、录音时间及说明在 VoiceOS 展开查看。“精简提醒显示”可去掉已有提醒的自动备注，保留你自己写的备注。VoiceOS 任务列表默认折叠详情，点目标展开。
新任务同步前，外部 API 直接提取明确说出的日期、通知时间和优先级，经原话与来源校验后通过 EventKit 保存；相对日期依据录音所在地时区，00:00–03:59:59按前一天理解，04:00起按当天理解；应用先计算绝对日期供模型使用，常见相对日还会本地校验。实际录音时间和原话保留，明确日历日期优先。来源时间不明或措辞含糊时留待核对，不猜测。截止日期不会自动变成通知。展开任务的“日期、提醒与优先级”可手动设置，保存后回读核对；在 Apple 提醒事项中修改的设置会读回 VoiceOS，后续同步不会自动覆盖。公开 EventKit 接口未提供标签、旗帜或“紧急”的读写，本阶段支持日期、通知、优先级和已有的完成状态同步。
已有任务也可直接复用逐字稿核对日期字段：`voiceos-check reminder-fields <资料库目录> <模型配置> <任务ID...>`，只保存本地核对结果，不写入 Apple 提醒事项，也不重新转写或提取任务。
“导入文件 → 已完成的全文整理”可以接回之前保存的清单，同一清单不会重复创建任务。
任务分类使用保存的意图类型及跟进状态；“问题与目标”还可单独查看问题、长期目标、想法与需求。
“核对为待办”可以将待核对、问题或长期意图明确为实际任务；保留原始意图与出处。“回听原话”直接播放对应录音段落并在该段结束时暂停。

“设置 → 自动接收录音 → 启用 VoiceOS收件箱”创建 `个人播客/VoiceOS收件箱`，以后放入的个人音频、视频自动串行整理。三音轨视频固定分别处理音轨 1（本人麦克风）与音轨 2（系统声音），混音轨 0 不重复分析；普通音频使用唯一音轨，其他多音轨格式需手动选择。每 10 秒检查一次，文件连续两次检查保持不变后才开始，完整处理、不移动或删除原件。内容去重、已处理文件状态及处理记录随重启保留，已完成或等待重试、且未变化的大视频不会反复读取全文计算哈希；失败后从界面重试。
处理中重开应用会恢复队列；临时服务失败最多尝试三次，分别等待一分钟、五分钟。界面显示正在处理、等待重试或需要手动处理及原因，失败的素材不会挡住后来加入的文件。暂停入口后不自动重试；权限问题和主动停止等待用户处理。
“连接语音备忘录”选择 Mac 上同步的语音备忘录目录；iPhone、Apple Watch 和 Mac 需使用同一 Apple 账户并开启语音备忘录 iCloud 同步。macOS 可能要求允许 VoiceOS 读取该目录；未获权限时会显示实际问题，不会声称已接通。连接时已有素材留在原处，只接收以后新增或更新的录音。自动入口需要 VoiceOS 打开、Mac 唤醒及 Qwen、文本模型已配置。

更正录音原文后，应用自动排入当前理解更新；连续表达按完整旧分组一起处理，节目更正会接续关联的本人录音。明确的相同行动沿用原任务身份、真实完成和反馈；转写纠错不会被写成用户撤回承诺。原话版本、历史理解与结果仍可追溯。
